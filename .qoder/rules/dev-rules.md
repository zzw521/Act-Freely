# 开发规范

## 外部接口 Mock 开关规范

当工程中存在对外部接口的依赖时，必须提供 Mock 开关机制，以满足以下要求：

1. **开发阶段**：开启 Mock 模式，使用本地模拟数据进行自测，无需依赖外部服务的可用性。
2. **联调阶段**：关闭 Mock 模式，调用真实的外部接口进行集成测试。

## 远端中间件 Mock 开关规范

当工程中存在对远端中间件（如消息队列、缓存、数据库等）的依赖时，必须提供 Mock 开关机制，以满足以下要求：

1. **开发阶段**：开启 Mock 模式，使用中间件的本地实现（如内存队列、本地缓存、嵌入式数据库等）进行自测，无需依赖远端中间件服务的可用性。
2. **联调阶段**：关闭 Mock 模式，连接真实的远端中间件服务进行集成测试。

## 测试覆盖规范

核心代码必须具备完善的测试覆盖，以保证代码质量和功能正确性，具体要求如下：

1. **单元测试（Unit Test）**：针对核心模块、函数、类的内部逻辑进行测试，覆盖所有关键代码分支（包括正常路径、异常路径、边界条件等），重点验证内部业务逻辑的正确性，而非仅验证接口定义是否正确。
2. **契约测试（Contract Test）**：针对服务之间的接口交互进行测试，验证服务提供方与消费方之间的契约一致性，确保接口的输入输出符合约定。
3. **端到端测试（E2E Test）**：针对完整业务流程进行测试，模拟真实用户场景，覆盖从入口到出口的完整链路，验证系统整体功能的正确性。

### 测试覆盖要求

- **关注内部逻辑**：测试用例需深入覆盖代码的内部分支和逻辑路径，而不是仅停留在接口签名或返回值类型的验证上。
- **分支覆盖率**：核心代码的分支覆盖率应达到团队约定的标准（建议不低于 80%）。
- **异常场景**：必须覆盖异常处理逻辑，包括错误输入、依赖失败、超时、并发冲突等场景。
- **可维护性**：测试代码需保持清晰、可读、易维护，避免过度耦合实现细节。

## 工程初始化脚本规范

每个工程**必须**在根目录提供一个 `init.sh` 脚本，供开发人员和自动化 Agent 快速搭建并启动开发环境。

### 脚本职责

`init.sh` 脚本须完成以下三项核心工作：

1. **安装依赖**：自动检测并安装工程所需的所有依赖（如 `npm install`、`pip install`、`go mod download` 等），确保环境开箱即用。
2. **启动服务**：根据当前阶段（开发/联调）拉起必要的本地服务或远端服务，包括但不限于：
   - 开发阶段：启动 Mock 服务、本地数据库、内存队列等。
   - 联调阶段：连接真实中间件，启动应用服务。
3. **输出访问信息**：服务启动完成后，在终端打印清晰的访问指引，包括：
   - 应用访问地址（如 `http://localhost:3000`）
   - API 文档地址（如 Swagger UI 地址）
   - 当前运行模式（Mock 模式 / 真实模式）
   - 其他关键配置说明

### 脚本示例结构

#!/bin/bash
set -e

echo "========================================="
echo "  工程初始化启动脚本"
echo "========================================="

# 1. 安装依赖
echo "[1/3] 正在安装依赖..."
# npm install / pip install -r requirements.txt / go mod download 等

# 2. 启动服务（默认开发阶段开启 Mock 模式）
echo "[2/3] 正在启动服务..."
# MOCK_ENABLED=true npm run dev / python main.py 等

# 3. 打印访问信息
echo "[3/3] 启动完成！"
echo "-----------------------------------------"
echo "  应用地址:     http://localhost:3000"
echo "  API 文档:     http://localhost:3000/docs"
echo "  运行模式:     Mock 模式（开发阶段）"
echo "-----------------------------------------"

### 规范要求

- `init.sh` 必须具备**可执行权限**（`chmod +x init.sh`），并在 README 中说明用法。
- 脚本须支持**幂等执行**，多次运行不产生副作用（如依赖已安装则跳过）。
- 通过环境变量（如 `MOCK_ENABLED=false`）控制 Mock 开关，方便切换开发与联调阶段。
- 脚本执行失败时应有明确的错误提示，便于快速定位问题。
