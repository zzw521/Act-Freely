# 文档索引

任我行的文档只保留三份现行文件：产品与排期两份，另加一份 Agent 平台层设计。历史规格、调研、台账与实施记录已归档，不再维护。

## 现行文档

| 文档 | 用途 | 什么时候读 |
| --- | --- | --- |
| [产品需求文档（PRD）](PRD-任我行.md) | 产品定位、用户、竞品、信息架构、功能需求、非功能要求、版本规划 | 评估需求、设计功能、对齐范围 |
| [缺陷与实现计划](缺陷与实现计划-任我行.md) | 缺陷台账、根因、方案、工作量、依赖、里程碑与验收 | 排期、修复、发布评审 |
| [Agent 平台层](agent-platform.md) | 消息总线、技能包、MCP Catalog、通道网关的分层、开关、CLI 与测试方式 | 改动 `engine/agent_platform/` 或接入新通道 |

## 阅读顺序

1. 先读 PRD 第 1–3 章，理解产品定位、竞品差异与信息架构。
2. 再读 PRD 第 4 章，按模块查看需求与实现状态。
3. 需要排期或修复时，读缺陷文档第 2 章总表，再定位到对应条目。
4. 发布前读缺陷文档第 6、8 章，核对里程碑与验收矩阵。
5. 只改平台层时，直接读 Agent 平台层的分层、开关与测试方式三节。


## 状态约定

| 标记 | 含义 |
| --- | --- |
| 已实现 | 主链路可用并通过测试 |
| 有限实现 | 可用但有明确边界 |
| 未验证 | 代码完成，缺少真实外部条件验证 |
| 未实现 | 仅有占位或规划 |

## 维护规则

- 新需求先进 PRD，再进缺陷文档排期；不新建平行规格。
- 功能状态变化时，同时更新 PRD 状态列与缺陷文档对应条目。
- 归档目录只增不改；需要恢复某份历史文档时，从归档复制，不要直接改归档。
- 文档中的路径、命令与版本号必须与代码一致；发版前检查一次。
