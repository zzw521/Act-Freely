# Super-agent 对标：DeepSeek Harness（DSH）的 Super-agent

**目的**：把 DSH 公开的原型与设计文档读成可执行工程结论，判断任我行要补哪几层，而不是照抄名词。
**证据口径**：§1–§3 的事实来自 2026-11-02 从 `github.com/deepseek-ai/dsh-superagent-prototype`（MIT）拉取的 `README.md`、`SETUP.md`、`docs/000–008`；§4 的任我行事实以当前源码为准，文档说法与源码不一致时以源码为准并在表中标出。
**必须记住的前提**：该项目首页自述为 **research prototype，不是 DeepSeek 官方产品**，且"文章里讨论的部分设计是未来方向，原型里没有实现"。**我们没有运行过它的代码**，因此不把它宣称的效果当承诺；媒体转述的团队自测数字（p95 完成时间 15.7 分钟 vs 单会话 29.5 分钟、token 更多）属二手信息，本文只作为"要自己测什么"的提示，不作为目标值。

## 1. 它到底解决什么问题

任我行今天的智能体是**会话中心**的：人提一个目标 → Rust harness 或 Python 引擎跑一轮 → 交付结果。DSH 的判断是这套的瓶颈不在模型，而在**人的注意力**：一个人同时只能盯 3–5 个活跃会话，每个会话的结论互不相通，全貌只有人自己知道；把一个员工挂所有事又会串味、变慢。

它的回答是把智能体做成**常驻系统**，六条骨架：

1. **事件驱动摄取**：环境里发生的事（Issue 评论、群消息、CI 结果）是输入，不靠人每次重新交代背景。
2. **双层授权**：确定性的准入（谁能开工、多强）在前，模型研判在后；主动干活必须命中团队写下的规则。
3. **工单化的工作单元**：一件"被授权的工作"是有状态机的实体，不是一段对话。
4. **每工单一个执行体**：独立会话 + 独立目录 + 槽位并发；主会话只做路由，不亲自干活。
5. **耐久副作用与可恢复**：所有外发动作先落队列再执行；重启带"恢复注记"，禁止重复外部动作。
6. **面板只显示需要人的东西**：健康状态不占版面。

第一性原则写在 `docs/000-philosophy.md`：**尽量少占用人的注意力，尽量多给价值**——每条消息、每个设置、每个面板元素都要值回一个人的注意力，否则删掉。推论很硬：**只在被要求、或团队写了规则时才动手；只有人必须行动或能用上结果时才说话**；干活过程中保持安静。

## 2. 概念模型（`docs/001-domain.md`）

| 概念 | 定义 | 关键规则（为什么这么定） |
| --- | --- | --- |
| Source | 一条事件流；kind 是可复用实现，instance 是一份配置 | 自己持有**读取位置**，重启不重放事件 |
| Trigger | 一条不可变事件 + Source 自己的元数据（含 actor） | 同一 Trigger 重复接单只创建一个工单 → 审计与幂等的单位 |
| Thread | Trigger 的时间序列 | 同一 Thread 同时**只跑一个 Eval**，期间到达的合并进下一批 |
| Correlation | 一个 Trigger 所属多个 Thread 之间的关系 | 只加上下文，**永不路由** |
| Channel | Thread 的写侧 | 确认、回复、PR、评审答复都是"写"，统一走 Outbox |
| Policy | 版本化的研判规则 + 每个 Source 的许可名单 / 准入表 / bot 名单 | 规则变了要**丢弃在跑的 Eval** 并重排队 |
| Eval | 对一批 Trigger 的判断：gate（确定性准入）+ assessment（模型研判） | 自身**不持状态**，输出 Decision |
| Mandate | 接单授予的东西：Policy 版本、范围、强度、命中规则、发送者身份 | 不可变；范围变宽=新工单；**只有人的停止能撤销**，续跑前重新校验 |
| Ticket | 一个被授权的工作单元 | 只能由 Eval 创建；自己定义状态，不跟随执行体会话状态 |
| Assignment | 工单绑定到某个执行体实例 | 一个工单先后有多个；只有它的最终报告能结束工单 |
| Subscription | 工单与 Thread 的多对多 | 匹配 Trigger **扇出**给订阅工单当上下文，**绕过准入、不给新授权**；人后来的消息不用再 @ Agent |
| Report | 执行体回报的状态 | `progress / waiting / ready / blocked / failed / dropped` 六种，结构化 |
| Attention | 等一个人回答的问题 | "需要人"必须由结构化字段判定，**不从报告自由文本猜** |

Decision 只有 `accept / stop / ignore / unavailable` 四种；强度只有 `explicit / inferred / not admitted`。

**被明确拒绝的概念**（`docs/001-domain.md` 的 Rejected concepts，这一节比设计更值钱）：不做跨 Source 的身份映射（同一个人在不同平台的账号对应关系是提示词文本，不是实体）；不让 Eval 自己调度延时 Trigger（"等 N 小时"是一种 Source，Eval 从不等待）；不限制"一个 Thread 只能有一个活工单"；不在策略变更时取消在跑工单（记录并送达，不撤回）；不因执行体失败就锁死它的全部工具（暂停自动输入即可）。

## 3. 执行与授权的两条硬机制

**主动干活的三档模式**（`docs/002-authorization.md`）：`off` 不产生任何推断候选；`observe`（默认）研判照做，但阳性结论只记成"本可接单"（ignore + would-accept 标记），**不执行**；`auto` 才真接。原文建议从 `observe` 开始，看过记录的 Decision 后再切 `auto`。范围更宽的工作必须新工单、新 Mandate。

**执行体的资源与恢复语义**（`docs/003-execution.md`、`docs/007-architecture.md`）：

- 每工单一个 `worker-<id>` 会话与一个按工单短名建的目录；目录不存在时先跑一次 prepare 命令（典型是 `git worktree`），十分钟超时，失败即工单失败。
- 并发上限作用于**worker 槽位**，另外**永久留一个槽给人**：人继续已有工单的唤醒不会被新任务挤掉。
- 回合结束但后台作业/子 Agent 还在跑 → 保留槽位、状态仍是 working，不上报 waiting；后台工作最多 30 分钟，到点杀作业并如实报告"被杀的是什么"。
- 交接给人时立即释放槽位；Assignment 结束时杀 shell 作业、释放子 Agent，替换的 Assignment 在关停完成后才启动。
- 瞬时故障（408/429/5xx、连接被拒/重置/超时）三次退避重试；`blocked / failed` 后**不再接受自动输入**，但工具仍可用，人可以直接在会话里接手。
- 重启：正在跑的 Assignment 以"host restarted"结束，新 Assignment 带**恢复注记**——先查目录、git 历史与 GitHub，再重复任何外部动作；"消息是否已被某个会话读进历史"这个事实也持久化，按步骤声明、在模型调用前落账。
- 所有外发（研判投递、启动、输入交付、中继、通知、回复）走**耐久副作用队列**：命令在事务内 `enqueue`，**提交后才执行**，按 kind 各有并发数与退避；同一工单发往同一会话的消息严格保序。状态存一个 SQLite 文件（`trigger / disposition / trigger_thread / thread / ticket / decision / effect / outbox / kv`，生成列 + 索引只扫活跃行）。
- 模型面被刻意收窄：主会话 14 个 `orchestrator_*` 工具，执行体只有 6 个；读页面有预算（文本默认 4000、最多 8000 个 UTF-16 单元；列表默认 20、最多 50 项）；主会话的 shell 里禁止 `sleep`、超过 30 秒的 timeout、超过 5 秒的 job 等待——**等待是排队，不是轮询**。

**结构性结论**：任我行缺的不是"更强的模型"或"更多工具"，而是**把智能体从会话升格为常驻工作系统**的那三层——事件入口与授权（D-46）、工单与待人工（D-47）、执行体运行时（D-48）。这三层与刚关闭的 D-06（事件订阅）和 D-34 / D-40 是同一条线，可以增量长出来，不需要重写 ReAct 主循环——这与 `docs/agent-platform.md` 定下的"增量落地、不重写主循环"一致。

## 5. 落地方案（分三段，每段可单独验收）

### 第一段 · D-46 事件入口与授权层（先影子跑）

- **Source 抽象**：`SourceKind`（读一次事件、产出 Trigger、保存游标、声明 Channel）+ `instance`（是否启用、监听什么）。首批三个源：账号服务项目事件（复用 `watch.rs` 已有的游标/退避/看门狗语义，把"刷新页面"换成"产出 Trigger"）、IM 通道入站消息（`engine/im_channels.py` 包一层，不改通道实现）、定时/条件源（"等 N 小时"是 Source，不是研判的一部分）。
- **Trigger 幂等**：`(source, source_event_id)` 唯一；重复接单只创建一个工单；游标只前进。安全边界沿用 D-06：access token 只进 Authorization 头与内存，不落日志、不进错误文案。
- **Policy + gate**：许可名单（按 Source 各自身份，不做跨 Source 映射）、准入表、`explicit / inferred / not admitted` 三强度、accept mode **默认 `observe`**。规则文本与命中记录进 SQLite，策略版本变更丢弃在跑研判并重排队。
- **验收**：① 关掉应用再打开，不重放历史事件；② 网络断 30 秒恢复，事件一条不丢不重复（沿用 `scripts/collab-live-acceptance.py` 的实测路子）；③ `observe` 下**没有任何自动执行**，但能导出"本可接单"清单与理由；④ 名单外的人 @ 也不开工（`not admitted` 有留痕）。
- **第二层研判落地状态（同日 1.6）**：DSH 的 Eval 分两层这件事，本段补齐了后一层——`gate` 判"这条事件有没有授权"（确定性、不花钱），`assess` 判"现在值不值得开工"（问模型）。`src-tauri/src/superagent/assess.rs` 只吃阳性候选，提示词里只带账本已有字段并把正文截到 600 字，输出限一行 JSON 的 `worth / not_worth / unsure` 加一句中文理由；解析不出结论就记 `unsure` 并保留模型原话，**不做任何猜测式放行**。它与 DSH 原型一致的三条纪律也都落地：研判有预算（策略新增 `assessMaxPerDay`，缺省 50，填 0 是显式关闭）、每条调用都过既有的 `QuotaGate`（token 在拿到响应之前就记进配额与用量表，失败也记）、结论只写回判定行（V17 给 `sa_decisions` 加 `assess_*` 七列，不新增表，也不创建任务）。与 DSH 不同的一点：它把研判结果直接接进工单与执行体，我们这一层的结果仍然只是清单上多一列"模型认为值不值得"，因为工单层（D-47）与执行体（D-48）还没落地——`auto` 档依然被 Rust 拒绝写入。IPC 从 13 条增到 14 条（新增 `superagent_assess_now`），页面在候选行显示结论/理由/模型/tokens 并给出「立即研判存量候选」按钮，导出的 CSV/JSON 也带上研判列。回归：Rust `superagent::` 74 条、全量 895 通过 / 0 失败；前端 vitest 2031 通过（`shadow-contract` 新增 9 条锁第二层）。**未验证**：真实模型上的调用与真实花费——所有单测都走"发起调用之前就返回"的路径（档位关闭 / 预算为 0 / 预算已满 / 无待研判 / 配额阻断），没有一条会请求模型；候选量是否值得这一层也要等真机跑一天才有依据。
- **「规则变了要丢弃在跑的 Eval 并重排队」落地（同日 1.7，#111–#114）**：上面第 89 行那句计划口径此前只做到了「换版本后老候选不再追研判」——队列直接按 gate 的 `policy_version` 取行，策略一升版，存量待研判候选既不出现在「待研判」统计里也永远不会再被问一次，等于静默丢空。现在把两个版本键分成两列：`policy_version` 只回答「当时依据哪一版策略判出来的」（留痕，永不改写），`assess_queue_version` 回答「这一行现在排在哪个版本的研判队列里」，V18 加这两列（外加 `requeued_at_ms` 重排时刻与一条按（队列版本, 研判状态）的索引），不新增表，存量行的队列键回填成自己的 gate 版本，所以升级本身不会凭空产生重排。`save_policy` 每次保存都按当前生效版本重排一次「还没研判的阳性候选」并把条数交给界面（已研判的不重排：重判等于为同一个判断再花一次模型钱；阴性本来就不在队列里；这一步幂等，内容没变时也照样走一遍，所以队列键落后于当前版本的候选——上一次保存重排失败留下的、以及 V17 时代留下的——再点一次「保存策略」就能自愈）。与 DSH 原型有一处有意的实现差别：它靠取消在跑的 eval 任务来丢弃，我们不开取消链路，而是在回写时按队列版本拒收——`record_assessment` 变成三态 `Written / AlreadyJudged / Superseded`，模型还在回答时策略升了版，这一轮的结论就作废、候选按新版重排后再判一次。效果一致（旧结论不生效），差别是那几次调用的钱已经入账不退，所以作废条数（`superseded`）进本轮摘要、由 Rust 拼成中文说明显示，不假装没花过钱。回归（本轮实测）：Rust 全量 913 通过 / 0 失败 / 1 忽略（`superagent::` 79 条），vitest 101 个文件 2038 通过，`shadow-contract` 32 条（第二层那组从 9 条增到 12 条）。仍未验证的部分没变：真实模型调用与真实花费、真机上「改一次策略后存量候选被按新策略重新问一遍」，以及 observe 连跑一天与重启不重放（#102）。
