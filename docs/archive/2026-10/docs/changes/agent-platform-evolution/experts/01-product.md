# 产品专家分析报告

> 专项任务：agent 办公系统三层架构（Agent 平台 Backend-Only / 用户端 Full-Stack / 管理控制台 Full-Stack）需求分析
> 定位：现有「通天办公」云端体系（spec-通天办公-云端与账号体系.md v1.0）的演进版本，聚焦差异与增量
> 约束基线：DAU ~50K，峰值并发会话 ~2000，并行任务受上限控制，模型调用限流降级，token 成本预算管控
> 引用约定：「主 SPEC」= spec-通天办公.md v2.1；「云端 SPEC」= spec-通天办公-云端与账号体系.md v1.0；「占位清单」= spec-通天办公-占位能力清单.md v1.0

## 1. 结论摘要（200-400 字）

三层架构需求的本质，是对云端 SPEC §2 现有六组件集群（Auth/Sync/Runner/Gateway/Files/Admin）做**结构性重组**而非从零设计：将 Runner+Gateway 下沉为独立的 Agent 平台（Backend-Only），新增现有设计完全缺失的「知识」能力与「平台运营」视角，并将现有 `/api/v1` 直映射契约（云端 SPEC §5.1）演进为「用户端后端 / 管理端后端」两个 BFF，以满足「前端不得直连平台」的边界约束。北极星指标定为「周 Agent 交付任务数」，按 DAU 50K、人均 2.5 任务/日、一次完成率 85%（继承主 SPEC §9.3）推导，GA+16 周目标为：周交付 ~74 万任务、D7 留存 ≥30%、D30 ≥18%、组织付费转化 ≥5%、单任务模型成本 ≤¥0.3。MVP 边界 = 云端 Phase A 全量 + Phase B 核心闭环 + 平台抽离（限流降级、并发调度、预算硬控三项新增 P0）+ 控制台组织视角 P0；明确不做企业级全量 RAG、技能市场交易、IM 集成、组织自定义 Agent 发布。最高风险为：知识能力现状零基础、峰值容量与预算管控在现有设计中无量化设计、BFF 边界与现有「契约复用」原则冲突。

| 编号 | 风险描述 | 等级 | 依据 |
|------|----------|:----:|------|
| R1 | 知识能力在现有设计中完全缺失：云端 SPEC §2 六组件无知识服务；占位清单 §2 中 AwarenessPage（记忆/感知）为纯占位且列 P2；主 SPEC 仅有工作区级 MEMORY.md 文件约定。新需求将「知识」列为平台基础能力，存在范围与排期双失控风险 | 高 | 云端 SPEC §2；占位清单 §2；主 SPEC §4.4 |

## 4. 待澄清问题

1. 「用户端」是否包含桌面端形态？还是仅指 Web 端？
   **推荐答案**：用户端 = 同一产品的桌面（Tauri）+ Web 双形态，均经用户端后端接入平台；桌面端本地能力（file_*、sandbox）保持 local-first（主 SPEC §10、云端 SPEC §1 定位不变），仅云端能力走 BFF。
2. 知识能力在 MVP 的深度：工作区文档问答，还是企业级知识库（含权限、目录、图谱）？
   **推荐答案**：MVP 仅工作区级文档知识库（上传→切片→检索→问答）；企业级知识库含权限隔离列入 Phase C 之后，避免击穿排期（见 S6）。
3. token 成本的承担模式：平台补贴（含在订阅内）还是组织按量付费？
   **推荐答案**：双轨制——免费用户由平台补贴 10 万 token/人/月；付费组织购买配额包、超额按量计费；该口径同时是预算硬停（S5）的计费基础。
4. 「agent 管理」的对象范围：仅平台预置 Agent，还是支持组织自定义 Agent 的创建与发布？
   **推荐答案**：MVP 仅管理预置 Agent（启停/模型绑定/配额）；组织自定义 Agent 发布列 P1，且须经平台审计后上架（见 S8）。
5. DAU 50K 的口径：全产品（桌面+Web）还是仅云端/Web 端？
   **推荐答案**：全产品口径；其中 Web 端 DAU 占比目标按 Phase B 验收 ≥20%（约 1 万）起步，GA+16 周提升至 ≥30%，峰值 2000 并发会话按云端侧容量设计。
6. 并行任务上限的分配方式：平台全局池统一控制，还是按组织配额切分？
   **推荐答案**：全局池 2000 并发会话 + 组织默认上限 5%（100）+ 用户上限 5，付费档位可上调组织上限；超限排队而非拒绝（见 S2）。
7. 管理控制台的「审计」范围是否包含模型调用的 prompt/response 内容级审计？
   **推荐答案**：MVP 仅元数据级审计（调用方、模型、token、耗时、敏感度标签，延续云端 SPEC §7 审计表口径）；内容级审计涉及隐私合规评估，列 P1 且默认脱敏（主 SPEC §9.4 脱敏规则延续）。
8. Phase A（桌面端云接入）与平台抽离的实施顺序：串行还是并行？
   **推荐答案**：Phase A 维持原计划先行（Auth/Sync 是两端的账号基础），平台抽离（S1/S3）与 Phase B 并行实施；Phase A 期间 Web 端暂以现有 `/api/v1` 直连模式过渡，B 阶段完成 BFF 切换。

## 附录 C：功能优先级（三层 P0/P1/P2）

## 附录 D：MVP 边界

### D.1 首版功能集（MVP = 云端 Phase A 全量 + Phase B 核心 + 平台抽离 P0 + 控制台 P0）

1. **账号与同步**（Phase A 原样）：注册/登录、桌面端数据单向上云、Settings「账号与同步」区块；未登录全功能可用（云端 SPEC §9 验收标准保留）。
2. **用户端 Web 闭环**：对话→计划审阅→执行→交付；附件/产物；任务排队反馈；降级提示。契约延续云端 SPEC §5.1 映射，经用户端后端 BFF 暴露（S3）。
3. **Agent 平台 P0 面**：任务执行引擎、模型网关（三级配额+降级链）、全局并发调度、Agent 注册表、计量管道。
4. **控制台 P0 面**：组织/成员、成本看板、出域硬开关、基础审计查询。
5. **限流降级与预算硬控**（S2/S5）：作为 MVP 验收硬指标——峰值 2000 会话不雪崩、超限 100% 走降级、预算 100% 硬停。

## 附录 E：与现有云端 SPEC Phase A/B/C 功能范围差异对比

| 阶段 | 现有设计范围（云端 SPEC §9） | 三层架构需求的差异与增量 | 影响评估 |
|------|------------------------------|--------------------------|----------|
| Phase A（桌面端云接入，~4 周） | Auth 服务 + 桌面端登录；Sync v1 单向上云 | **范围基本不变**；增量：账号模型需预埋组织字段（云端 SPEC §4.2 已有 organizations 表，可复用）；登录态需兼容后续 BFF 双端注入 | 低增量，维持原排期 |
| Phase B（网页版，~6 周） | http-api.ts 适配层；Runner 容器池 + Gateway v1；Files 服务；Web 闭环 | **结构性变更**：① Runner/Gateway 从「云端服务集群组件」降格为 Agent 平台内部组件，新增平台对外内部 API 层（S1）；② 新增用户端后端 BFF，`/api/v1` 由 BFF 承接而非直连平台（S3，与云端 SPEC §5.1 直映射模式差异最大处）；③ 新增全局并发任务调度/排队（2000 会话池，现有设计完全缺失）；④ 新增三级配额+降级链+预算硬停（Gateway v1 原仅「计量」）；⑤ 知识服务 v0 视排期决定是否挤入本阶段（建议不挤入，列 B 与 C 之间） | 高增量，建议排期 +2~3 周（6→8~9 周） |
| Phase C（团队与管理后台，~6 周） | Organization/RBAC + Admin API；管理后台（成员/用量/审计/安全策略）；组织级技能与连接器分发 | **范围扩展**：① 管理后台从 org admin 单视角扩展为双视角（+平台运营，S7）；② 「资产中心」升级为「Agent 管理」一级模块（预置 Agent 启停/绑定/配额，S8）；③ 用量配额从「阈值告警」升级为预算硬停+降级联动（S5）；④ 审计增加组织级策略执行记录 | 中增量，建议排期 +1~2 周 |
| 全程新增 | — | 北极星与漏斗埋点体系（S9）贯穿三阶段；每阶段验收增加量化指标行（附录 B.3）替代现有定性验收语（云端 SPEC §9 现验收为「数据可见于云端」类描述） | 横向要求 |

**核心差异总结**：三层需求不是替换云端 SPEC，而是三处结构性增量——（1）组件重组（Runner/Gateway → 平台层）；（2）契约加层（直映射 → BFF 分层）；（3）能力补全（知识、全局调度、预算硬控、平台运营视角四项现有设计零覆盖）。Phase A 可原样执行，Phase B/C 需按上表扩容。
