# 架构专家分析报告

> **专项视角**：架构（系统边界 / 模块拆分 / 容量瓶颈 / 长任务稳定性 / 限流降级与预算管控）
> **输入文档**：`docs/spec/spec-通天办公.md` v2.1（下称「主 SPEC」）、`docs/spec/spec-通天办公-云端与账号体系.md` v1.0（下称「云端 SPEC」）、`docs/spec/spec-通天办公-占位能力清单.md` v1.0（下称「占位清单」）
> **约束基线**：DAU ≈ 50K；峰值并发会话 ≈ 2000（含 SSE 长连接）；并行任务受上限控制；模型调用限流降级、token 成本受预算管控

---

## 1. 结论摘要

三层架构（Agent 平台 Backend-Only + 用户端 Full-Stack + 管理控制台 Full-Stack）相对现有云端 SPEC §2 的六组件集群是**结构性演进而非推倒重来**：Auth/Files/Sync 以复用为主，Runner/Gateway 需升级为平台级服务，Admin 需拆分为组织自服务与平台运营两套，知识服务与 Agent 注册为全新增量。现有设计存在四处硬缺口：① 云端 SPEC §2 架构为 Web 前端直连云端集群，违反「前端只依赖各自后端」边界，必须增设用户端 BFF；② 知识能力在现有三份文档中均无承载（占位清单 §2 AwarenessPage 仅 P2 占位）；③ Gateway 现有职责仅「计量/限流」，无预算台账与硬停机制；④ 云端 SPEC §10.1 仅有 5 项时延指标，无连接数/QPS/存储容量规划。按 DAU 50K、峰值 2000 SSE 连接估算：用户端 BFF 需承载突发 1500 QPS、事件总线峰值 ≥ 10K msg/s、Runner 峰值并发任务 500（约 250 vCPU）、PostgreSQL 月增约 150 GB、对象存储月增约 3 TB。Top3 瓶颈为 SSE 事件扇出与重连风暴、Runner 容器池成本与冷启动、模型供应商 RPM/TPM 限制与预算热点。核心裁决点：BFF 厚薄、预算强制点归属、并行上限数值。

## 4. 待澄清问题

1. **用户端后端定位：薄 BFF 还是厚业务后端（会话编排状态归应用层还是平台）？**
   推荐答案：薄 BFF。任务/计划/步骤的权威状态归平台 task-service（A-03），BFF 仅负责会话聚合、SSE 中继、面向前端的视图组装；理由：避免状态双写（R-09），且长任务跨设备续接必须依赖平台侧持久化。
2. **并行任务上限数值（全局 500 / 组织 50 / 用户 5）是否符合业务预期？**
   推荐答案：采纳本报告推导值并做成配置项。推导：峰值 2000 会话按 25% 处于执行态 ≈ 500；组织/用户级按主 SPEC §3.5.5 配额模型等比放大；实际值应在 Phase B 压测后校准。
3. **预算单位：token 量还是金额？**
   推荐答案：双台账。token 量为主计量（与供应商口径一致），按模型单价折算金额做预算硬停与报表；金额台账支撑管理控制台「成本」模块。
4. **管理控制台服务对象：平台运营方还是企业管理员，一个应用还是两个？**
   推荐答案：本期做「平台运营方控制台」独立应用；企业管理员沿用云端 SPEC §8 管理后台演进形态，二者共享控制台后端的权限/审计模块、前端独立部署。
5. **事件总线选型（Redis Streams / NATS / Kafka）？**
   推荐答案：Redis Streams。峰值 10K msg/s 在其能力范围内，且与云端 SPEC §3 已选 PostgreSQL 栈运维同构；Kafka 留作 3 倍流量后的演进选项。
6. **知识服务一期范围是否包含个人记忆？**
   推荐答案：不包含。一期仅组织/Agent 共享知识库（RAG 检索增强）；个人记忆对应主 SPEC P2 记忆系统与占位清单 AwarenessPage，另行立项。
7. **桌面端未来是否接入平台运行时（云端 Runner 替代本地执行）？**
   推荐答案：本期不接入。维持主 SPEC §1.3 local-first 原则与 §10.3 密钥边界；桌面端仅经 Auth/Sync 与云端交互，避免三层架构演进阻塞桌面主线交付。

| 前端只依赖各自后端，禁止直连平台 | ① 平台 API 部署私有子网，无公网入口，入站仅允许两个后端的服务网段；② 平台域名不出现在前端 CSP `connect-src` 与构建配置中（主 SPEC §6.4 CSP 模式延续）；③ 平台不配置面向前端域名的 CORS；④ 前端 SDK 仅内置各自后端 base URL，CI 静态检查禁止平台域名常量 |
| 后端→平台使用服务凭据，不透传用户裸 JWT | 后端以 mTLS + client_credentials JWT（scope 按平台能力域切分）调用平台；用户身份以声明字段（user_id/org_id）传递，平台校验调用方 scope 与声明一致性 |
| 禁止反向依赖（平台不依赖应用层） | 平台仅暴露同步 API + 领域事件；应用层订阅平台事件，平台不回调应用层；架构守护测试（依赖方向 lint）纳入 CI |
| 用户端后端与控制台后端互不依赖 | 二者平行调用平台，共享数据一律经平台查询，禁止横向调用 |

## 附录 B：模块拆分与六组件映射

### B.1 模块拆分

**用户端后端（BFF）**：① 会话与对话 API（chat_submit/review/control/history 的 REST+SSE 代理，契约沿用云端 SPEC §5.2 command 映射）；② SSE 中继与重连缓存（Last-Event-ID 重放）；③ 文件上传代理（转 Files 预签名）；④ 用户设置与偏好；⑤ 知识库用户视图（检索代理）；⑥ 用量自查（预算余额预检）。

**管理控制台后端**：① agent 管理 API（注册/版本/发布审批/下架）；② 权限与策略 API（组织配额、出域硬开关下发，复用云端 SPEC §7 语义）；③ 审计 API（双源归一检索/导出）；④ 成本 API（预算台账、账单聚合、阈值告警）；⑤ 平台监控 API（队列深度、池水位、熔断状态）。

**平台服务**：auth-service（身份+组织+服务凭据）、agent-service（注册中心）、task-service（编排+状态权威）、runtime-pool（Runner 容器池）、knowledge-service（摄取/索引/检索）、model-gateway（接入/限流/熔断/预算预扣）、metering-service（计量计费）、file-service（对象存储）、event-bus（领域事件与 SSE 事件流）。

## 附录 C：容量与负载估算（DAU 50K / 峰值 2000 并发会话）

### C.1 基础假设（显式声明，供业务校准）

| 假设项 | 取值 | 推导/说明 |
|--------|------|-----------|
| 峰值小时活跃用户 | 15,000（DAU 30%） | 办公场景上午/下午双峰，峰值小时集中 |
| 人均会话数 | 8 次/日，均值时长 8 分钟 | 15,000×8/8h = 4.2 会话/s 到达率 × 480s ≈ 2000 并发，与给定峰值自洽 |
| 执行态会话占比 | 25% | 其余为审阅/等待/浏览态 → 峰值并发执行任务 ≈ 500 |
| 人均任务数 | 2 次/日 | 全局 100K 任务/日 |
| 单任务模型调用 | 10 次 × 3K tokens | 对应主 SPEC §3.1 计划+逐步执行模式 → 30K tokens/任务 |

### C.2 各层负载与容量规划

| 层/组件 | 负载估算 | 规划值 |
|---------|----------|--------|
| SSE 长连接 | 峰值 2000（给定）；每连接心跳 15s → 约 133 心跳/s | 接入层 3 节点 × 1500 连接容量（N+1，单节点故障余量 50%）；axum/tokio 单节点实测能力 >5K，取保守值 |
| 事件扇出 | 峰值流式会话约 500 × 15 块/s ≈ 7.5K events/s，加状态事件取 **10K msg/s** | event-bus 吞吐 ≥ 10K msg/s、端到端延迟 ≤ 500ms（云端 SPEC §10.1 指标延续） |
| 用户端 BFF | 15,000 峰时用户 × 40 请求/用户时 ÷ 3600 ≈ 167 QPS 均值；突发 ×3 | 设计 500 QPS、突发 1500 QPS；实例 ≥ 2（4C8G） |
| 平台内部 API | BFF+控制台调用合计 ≈ 600 QPS 均值 | 每域服务 ≥ 2 实例；平台整体按 2000 QPS 压测验收 |
| 任务并发 | 峰值 500 执行态 | 全局上限 500 / 组织 50 / 用户 5；有界队列深度 1000，超限返回 429+Retry-After |
| Runner 容器池 | 500 并发 × 0.5 vCPU/1GB ≈ 250 vCPU | 热池 100、冷启动 ≤ 5s、池满排队降级；每任务容器隔离（云端 SPEC §7） |
| model-gateway | 500 任务 × 并行 3 调用（主 SPEC §3.5.5）= 1500 并发上游调用峰值；均时 3s → 持续约 500 调用/s ≈ 30K RPM | Gateway 设计 1000 调用/s；供应商侧按多供应商分摊 RPM/TPM，单一供应商占比 ≤ 60% |
| token 吞吐 | 100K 任务/日 × 30K tokens ≈ **3B tokens/日 ≈ 90B/月** | 预算台账按组织月度额度管控；峰值 TPM 需求 ≈ 500 调用/s × 3K ≈ 1.5M TPM（供应商配额须匹配，缺口经排队吸收） |
| PostgreSQL | 消息 3GB/日 + 任务/计划 1GB/日 + 审计 1GB/日 ≈ 5GB/日 ≈ **150GB/月** | 热数据 6 个月 ≈ 1TB；按月分区，审计与 sync_log 90 天后归档对象存储 |
| 对象存储 | 产物/附件 50K×2 文件/日×1MB ≈ 100GB/日 ≈ **3TB/月**；知识库增量约 20GB/日 | 90 天转低频层；知识库文档与向量索引独立生命周期 |
| 计量写入 | 峰值 500 调用/s × 每调用 1 事件 ≥ 500 TPS | 异步批量落账（批 100 或 1s），端到端 ≤ 5s |

### C.3 Top3 瓶颈与对策

| # | 瓶颈 | 量化证据 | 对策 |
|---|------|----------|------|
| 1 | SSE 事件扇出与重连风暴 | 10K msg/s 扇出；2000 连接若同时抖动，无重放机制则产生 2000 并发历史回捞（R-05） | seq + Last-Event-ID 重放窗口 ≥ 10 分钟；事件流经 event-bus 与接入层解耦；接入层按 task_id 粘性路由；单节点连接数硬上限 1500 触发主动迁移 |
| 2 | Runner 容器池成本与冷启动 | 峰值 250 vCPU；冷启动 >5s 直接击穿任务 P95（云端 SPEC §10.1 无此指标） | 热池 100 + 镜像预热；组织配额 + 全局上限 + 排队降级（云端 SPEC §10.2 既定方向量化）；闲时缩容至 20 |
| 3 | 模型供应商限流与预算热点 | 峰值需求 30K RPM / 1.5M TPM，单一供应商配额不可承受；热点组织可耗尽全局额度 | 多供应商路由分摊（单家 ≤ 60%）；集中式 RPM/TPM 令牌桶（Redis）；预算预扣 + 硬停（A-05）；429 退避复用主 SPEC §3.2.4（1s→8s×4） |

次级瓶颈（监控项）：PostgreSQL 写入（sync_log + 事件 + 审计合计峰值 ≈ 1.5K TPS，经异步追加与分区缓解）；审计双源聚合查询（控制台报表走日聚合表，不查原始表）。

## 附录 E：限流降级与预算管控落点

| 层 | 职责 | 量化规则 | 是否权威 |
|----|------|----------|:--------:|
| 边缘层（LB/API 网关） | 粗粒度防滥用：连接数、REST QPS、SSE 连接数 | 每用户 REST ≤ 20 req/s、SSE 连接 ≤ 5；超限直接 429 | 否（保护性） |
| 平台层（model-gateway） | **唯一权威强制点**：供应商 RPM/TPM 令牌桶、预算预扣/结算/硬停、熔断降级链、出域硬开关 | 令牌桶集中存储（Redis，解决多实例分裂，R-08）；预算 80% 告警/100% 硬停返回 `BUDGET_EXCEEDED`；熔断阈值复用主 SPEC §3.2.4（P95>8s 或连续 3 次切备用；错误率 5 分钟>15% 降级；熔断 180s）；出域硬开关联动云端 SPEC §7 | **是** |
| 应用层（两个后端） | 乐观预检（提交前查预算余额与队列水位）、限流响应透传（Retry-After）、降级 UX 与排队提示 | 预检仅减少无效提交，不作为拒绝依据；收到 `BUDGET_EXCEEDED`/429 必须透传用户可读原因 | 否 |

落点裁决理由：预算与供应商配额的并发一致性只能在单点（平台 Gateway）保证；放应用层会被绕过且双后端重复实现，放边缘层则拿不到 token 级语义。边缘层只做连接/QPS 保护，应用层只做体验。
