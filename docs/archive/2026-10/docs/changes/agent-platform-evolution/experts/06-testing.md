# 测试专家分析报告

> 视角：测试专家（验收标准 / Agent 行为可测性 / E2E / 压测 / 契约测试）
> 对象：三层 agent 办公系统演进（Agent 平台 Backend-Only + 用户端 Full-Stack + 管理控制台 Full-Stack）
> 约束基线：DAU ~50K、峰值并发会话 ~2000（SSE 长连接）、并行任务受上限控制、模型调用限流降级、token 预算管控
> 规范基线：外部接口与远端中间件必须有 Mock 开关（`MOCK_ENABLED` 控制）；测试分单元/契约/E2E 三层；核心代码分支覆盖率 ≥ 80%
> 引用文档：`spec-通天办公.md` v2.1（下称「主 SPEC」）、`spec-通天办公-云端与账号体系.md` v1.0（下称「云端 SPEC」）、`spec-通天办公-占位能力清单.md` v1.0（下称「占位清单」）

## 1. 结论摘要

现有两份 SPEC 已具备较好的测试基线（主 SPEC §8 测试金字塔、§9 非功能指标；云端 SPEC §10 指标与风险），但均为**单机/桌面形态**口径，无法直接覆盖三层云端形态。本报告的核心结论：① 验收指标需按三层重新分配——平台层新增「任务并行上限 100% 生效、限流生效延迟 ≤ 1s、预算硬停误差 ≤ ±2%、平台可用性 99.9%」四项硬指标；用户端将云端 SPEC §10.1 的 SSE 延迟拆分为「服务内 < 500ms（保留）」与「端到端 P95 < 1.5s（新增）」双口径；管理控制台新增「审计日志零丢失、配额变更 ≤ 30s 生效」两项指标。② LLM 非确定性必须用「结构断言 + 行为断言 + 语义评估器」三层策略替代字面匹配，黄金用例集 ≥ 120 条、回放一致性 100%、语义漂移以 7 日滚动基线 ±10% 告警。③ 压测以 2000 SSE 并发为红线，通过线为 SSE 断开率 = 0、API P99 < 1s、错误率 < 0.1%、CPU < 70% / 内存 < 75%。④ 「前端禁止直连平台」必须以 CI 静态扫描 + 出口代理强制 + E2E 违规检测三重手段测试化，否则架构约束无法被证伪。⑤ 最高风险：LLM 回放失真造成「测试全绿但线上行为漂移」（高）、压测环境与生产不一致导致指标失真（高）。

|------|----------|:----:|------|

## 4. 待澄清问题

1. **SSE 延迟验收口径**：云端 SPEC §10.1「SSE 事件端到端延迟 < 500ms」标注为「服务内」，但用户实际感知是端到端。建议答案：双口径并行验收——服务内 P95 < 500ms（平台责任边界）、端到端 P95 < 1.5s / P99 < 3s（用户端责任边界，含客户端渲染），压测报告分列两列。
2. **黄金集真实模型跑批预算**：漂移检测需要在真实模型（MOCK_ENABLED=false）上周期性运行黄金集。建议答案：每周全量跑批一次（约 120 用例 × 平均 3 轮调用），预算上限按当月模型预算的 2% 封顶，超限自动降级为抽测 30 条核心用例。
3. **压测环境与依赖真实性**：模型网关在压测中使用真实模型还是 Mock 回放？建议答案：默认 Mock 回放（验证系统自身容量，MOCK_ENABLED=true）；上线前做一次真实模型小规模联调压测（200 并发、15 分钟），验证限流/429/降级与真实厂商行为一致。
4. **任务并行上限的具体数值**：约束仅说「并行任务受上限控制」，未给出全局与单用户数值。建议答案：全局并行执行任务 ≤ 500、单用户 ≤ 3、单组织 ≤ 50；超限进入排队队列（队列深度上限 1000，超过返回 QUOTA_EXCEEDED）。需平台专家确认容量模型。
5. **预算管控粒度**：预算按组织/用户/任务哪一级强制？建议答案：组织月度预算为硬停边界（误差 ≤ ±2%），用户级为软限（告警 + 降速），任务级仅计量展示。需 TL 与平台专家共同裁决。
6. **管理控制台是否需要独立压测基线**：管理员并发量级远小于用户端。建议答案：控制台单列低压基线（50 并发管理 API、审计查询 P95 < 2s @ 100 万条审计数据），不与用户端共用通过线。
7. **回滚/中断在云端 Runner 形态下的语义**：主 SPEC §3.1.4 回滚机制基于本地文件备份；Web 端 Runner 容器内回滚如何实现。建议答案：Runner 容器卷快照 + 产物对象存储版本化，回滚成功率验收线沿用主 SPEC §9.3 的 ≥ 99%。需平台专家确认实现路径后再固化测试用例。

| 类别 | 用例数下限 | 内容 | 断言等级 |
|------|:---------:|------|----------|
| G1 状态机轨迹 | ≥ 30 | 提交→规划→审阅→执行→交付全路径 + 全部非法转移 | 确定性断言（与 LLM 输出无关，回放保证） |
| G2 规划质量 | ≥ 40 | 典型办公目标（周报/文件整理/数据汇总）→ Plan 结构合理性 | 结构断言 + LLM-as-Judge |
| G3 工具调用 | ≥ 30 | 给定目标断言工具调用序列（顺序/参数 schema/幂等重试） | 行为断言（轨迹级） |
| G4 安全与合规 | ≥ 20 | 危险操作拦截、敏感数据强制本地、预算耗尽拒绝 | 确定性断言 |

治理规则：每条用例含 `scenario_id`、固定 `seed/temperature=0`（真实跑批时）、输入快照、期望断言集、基线版本号；prompt 或模型版本变更 → 基线版本号 +1 并重新录制回放。

### 6.2 行为断言原则（断言什么 / 不断言什么）

**必须断言（确定性维度）：**
- 状态机轨迹：事件序列与主 SPEC §3.1.1 合法转移完全一致（如 `Plan → StepStart×N → Done`）
- 结构合规：Plan/Step JSON 通过 schema 校验；字段齐全、类型正确
- 副作用：文件产物存在且 SHA256 与预期结构匹配；审计落库条数与事件数一致；token usage 已记账
- 工具调用轨迹：调用工具集合、顺序、参数 schema（不比较参数自然语言内容）
- 边界行为：预算耗尽必拒、危险操作必拦、非法转移必报错

**禁止断言（非确定性维度）：**
- 逐字匹配 LLM 生成文本（摘要、回复措辞、Plan 步骤名称的自然语言表述）
- 步骤数量精确值（断言区间，如 3 ≤ steps ≤ 8）
- 措辞风格、排版细节等主观质量（交由评估器打分，不硬编码阈值到用例里）

**语义质量评估器（LLM-as-Judge）：** 对 G2 类用例由评估模型按固定 rubric（目标覆盖度/步骤可执行性/冗余度，各 0-5 分）打分；总分 ≥ 3.5/5 为通过；评估器本身用 20 条人工标注样本校准，评估器与人工一致率 ≥ 90% 方可启用。

### 6.3 回归基线与漂移检测

| 机制 | 规则 |
|------|------|
| 回放回归（CI，每次合并） | `MOCK_ENABLED=true`，全部黄金集回放运行，通过率必须 100%；任何失败阻断合并 |
| 真实模型周跑批 | 每周一次全量（见 Q2 预算），输出各维度通过率与评估分 |
| 滚动基线 | 以最近 7 日真实跑批结果为基线：任一关键维度（完成率/结构合规率/评估均分）偏差 > 10% → 告警；> 20% → 阻断发布并触发人工评审 |
| 漂移归因 | 漂移告警必须区分三类来源：模型版本变更（厂商侧）、prompt/配置变更（本系统侧）、评估器失真；归因结论写入用例变更记录 |

### 6.4 模型 Mock 回放策略（对齐 MOCK_ENABLED 规范）

1. **开关语义不变**：`MOCK_ENABLED=true` 全部模型调用经回放层，不产生真实调用与费用；`MOCK_ENABLED=false` 走真实网关（联调/周跑批）。
2. **回放匹配键**：`scenario_id + turn_index + model + normalize(prompt_hash)`。`normalize` 去除时间戳/UUID/路径中的随机段，避免无关差异导致 miss。
3. **Miss 策略（关键，防失真）**：回放 miss 时**测试立即失败**（fail-fast），禁止回退到规则生成或调用真实模型——静默 fallback 是 R2 失真根源。miss 详情（期望键 vs 最接近键）写入报告，驱动重新录制。
4. **录制流程**：联调阶段（MOCK_ENABLED=false）运行黄金集时同步录制响应入库，录制产物带模型版本号与日期；回放层校验录制版本与用例基线版本匹配。
5. **流式回放**：SSE 逐 chunk 回放保留原始 chunk 切分与间隔（可加速 ≤ 10×），验证用户端流式渲染与 usage 尾包处理。
6. **降级链回放**：为主模型录制「超时/429/5xx」故障响应，验证主 SPEC §3.2.3 降级链与 §3.2.4 熔断阈值（连续 3 次超时切换、5 分钟错误率 > 15% 降级）在回放模式下可精确复现。
7. **等价性抽测**：每月抽 10 条黄金用例同时跑回放与真实模型，比较状态机轨迹与工具调用轨迹一致率，≥ 90% 视为回放层可信；低于 90% 触发全量重录。

### 6.5 跨端续接必测场景（对应 §3-S10）

| 场景 | 步骤 | 验收点 |
|------|------|--------|
| E1 双端同任务并发 | 桌面端与 Web 端同时执行同一 task | 后提交方 100% 收到 `TASK_ALREADY_RUNNING`（云端 SPEC §6.3）；先执行方不受影响 |
| E2 离线续传 | 桌面端离线产生 ≥ 20 条待同步写入 → 联网 | `pending_count` 归零、无重复写入（`client_rev` 唯一约束生效）、延迟 ≤ 3s×批次 |
| E3 跨端任务续接 | Web 端发起任务执行中 → 桌面端打开同一任务 | 桌面端 SSE 订阅同一事件流，事件序号连续无缺口；两端状态一致 |

## 7. 压测标准

### 7.1 容量假设与场景矩阵

流量模型：DAU 50K，峰值小时活跃 ≈ 20%（10K），峰值并发会话 2000（SSE 长连接）；单会话平均每分钟 1 次交互 API 调用 → 峰值 API ≈ 35 req/s（交互）+ 任务提交脉冲。

| 编号 | 场景 | 负载配置 | 时长 | 目的 |
|------|------|----------|:----:|------|
| L1 | SSE 保持 | 2000 并发 SSE 连接，每连接每 30s 一次事件推送 + 心跳 | 30min | 验证 M12 长连接容量 |
| L2 | 交互 API 混合 | 50 req/s（读 70% / 写 30%），Poisson 到达 | 15min | API 网关与后端基线 |
| L3 | 任务提交脉冲 | 100 任务/min 突发 ×3 分钟，并行执行逼近上限（建议 500） | 15min | 验证 M13 排队与上限 |
| L4 | 模型网关吞吐 | 300 并发模型调用（Mock 回放，模拟真实延迟分布 P50=1.2s/P95=3s） | 15min | 验证 M5 网关开销与限流前置 |
| L5 | 混合叠加 | L1 + L2 + L3 同时施加 | 30min | 最接近生产的综合水位 |
| L6 | 稳定性浸泡 | L5 的 60% 负载 | 4h | 内存泄漏/连接泄漏检测 |
| L7 | 故障注入 | L5 运行中：平台单实例 kill、模型 Mock 全部 5xx、DB 主从切换各一次 | 各 10min | 验证 M10 可用性与自愈 |
| L8 | 控制台低压 | 50 并发管理 API + 审计查询（预置 100 万条审计数据） | 10min | 验证 M18 |

### 7.2 工具要求

- 协议支持：HTTP/1.1 + SSE 长连接并发保持（k6 0.5x+ 或 Locust 自研 SSE client）；压测机 ≥ 2 台（每台承载 1000 SSE），排除压测侧端口/fd 瓶颈（ulimit ≥ 65535 预检脚本）
- 可观测接入：压测期间平台必须输出 Prometheus 指标（连接数、队列深度、限流计数、预算余额），报告自动生成
- 数据准备：脚本化造数（5 万用户、2000 活跃会话上下文、100 万审计记录），数据可重置
- MOCK_ENABLED 联动：L1-L8 默认 `MOCK_ENABLED=true`（回放模型）；上线前追加一次 200 并发真实模型联调压测（见 Q3）
- 报告输出：每场景自动产出 P50/P95/P99、错误率、资源水位时序图；未达通过线的场景标红并阻断上线评审

### 7.3 通过线（全部量化）

| 维度 | 通过线 | 适用场景 |
|------|--------|----------|
| SSE 断开率 | = 0（服务端主动关闭除外）；心跳丢失重连成功率 ≥ 99.9%，重连 < 3s | L1/L5/L6 |
| API 延迟 | 交互 API P95 < 300ms、P99 < 1s；任务提交 P95 < 500ms | L2/L5 |
| SSE 事件端到端 | P95 < 1.5s、P99 < 3s（事件产生→客户端收到，对齐 M9 修订口径） | L1/L5 |
| 错误率 | HTTP 5xx < 0.1%；业务错误（非预期） = 0 | 全部 |
| 排队 | 超上限任务 100% 入队，入队确认 < 100ms；队列深度峰值 ≤ 1000 | L3 |
| CPU | 平台各实例峰值 < 70%（预留限流降级余量） | 全部 |
| 内存 | 峰值 < 75% 限额；L6 浸泡 4h 内存增长 < 10%（无泄漏） | 全部/L6 |
| 连接/fd | SSE 连接数与预期偏差 < 0.5%；无 CLOSE_WAIT 堆积（< 100） | L1/L6 |
| 故障恢复（L7） | 实例 kill 后服务恢复 < 30s；模型全 5xx 时 100% 触发降级且任务不丢失；恢复后 SSE 重连率 ≥ 99.9% | L7 |

### 7.4 限流降级与预算管控专项验证

| 编号 | 场景 | 步骤 | 验收点（量化） |
|------|------|------|----------------|
| T1 | 单用户限流 | 单用户以 2× 阈值速率调用 | 超限请求 100% 返回 429 + `Retry-After`；阈值内请求零误伤 |
| T2 | 组织限流 | 组织内 10 用户叠加超组织阈值 | 组织级限流生效，429 带组织配额标识；限流决策延迟 ≤ 1s |
| T3 | 限流规则热更新 | 压测运行中经控制台将阈值调低 50% | ≤ 1s 内新阈值生效（M14）；无规则空窗期 |
| T4 | 降级链 | 主模型 Mock 注入 P95 > 8s 延迟 + 连续 3 次超时 | 自动切换备用模型（主 SPEC §3.2.4）；切换期间任务不失败，用户收到切换事件 |
| T5 | 熔断 | 注入 5 分钟内错误率 > 15% | 熔断打开（180s），期间请求快速失败 < 100ms；半开探测成功后关闭 |
| T6 | 预算软限 | 组织消耗达预算 80% | 控制台告警事件 ≤ 1min 内可见；用户端收到降级提示 |
| T7 | 预算硬停 | 消耗达 100% | ≤ 5s 内新模型调用 100% 拒绝（错误码 BUDGET_EXHAUSTED）；已在执行的流式调用允许收尾但不新启 |
| T8 | 预算恢复 | 控制台追加预算 | ≤ 60s 内放行恢复；计量连续无跳变 |
| T9 | 计量准确性 | T1-T8 全程 | 平台计量与回放响应 usage 之和误差 ≤ ±3%；中断/重试无重复计费（M16） |
| T10 | 配额变更穿透 | 控制台调低组织并行任务上限 | ≤ 30s 生效（M17）；超出的执行中任务允许完成、新任务按新上限排队 |

## 8. 契约测试需求（两层契约 + 架构约束强制）

### 8.1 契约分层与测试手段

```
用户端前端 / 控制台前端
   │  ① 前端→后端契约（REST + SSE）
   ▼
用户端后端 / 控制台后端
   │  ② 后端→平台契约（平台 API + 模型网关）
   ▼
Agent 平台（Backend-Only）
```

| 契约层 | Schema 来源（单一来源） | 消费者测试 | 提供者测试 |
|--------|--------------------------|------------|------------|
| ① 前端→各自后端 | 后端 OpenAPI 3.1（由主 SPEC §5 的 32 个 command 映射，对齐云端 SPEC §5.2） | 前端：类型由 OpenAPI codegen 生成，编译期对齐；组件测试用 MSW 按 schema mock | 后端 CI：Schemathesis 模糊测试（500 请求/端点）+ 契约快照测试；SSE 事件载荷与主 SPEC §3.1.3 `AgentEvent` 枚举逐变体校验 |
| ② 后端→平台 | 平台团队维护 OpenAPI 3.1 + Rust 类型生成（对齐云端 SPEC §3 axum 选型与 ts-rs 模式） | 两个应用端后端各维护消费者驱动契约（Pact）：覆盖各自实际调用的端点与错误码（含 429/503/预算拒绝） | 平台 CI 运行全部消费者契约作为提供者验证；破坏性变更必须升主版本号并通知两消费者确认 |
| 错误码契约 | 主 SPEC §5.3 `AppError` 枚举 | 三层错误码映射表（平台码→后端码→前端码）作为契约文件，CI diff 检测 | 新增错误码必须先入契约后实现 |

### 8.2 版本兼容规则（量化）

- 兼容性矩阵 CI：后端 N 版本 ↔ 前端 N / N-1 版本契约测试必须全绿；平台 N ↔ 消费者 N / N-1 同理
- 字段增删改分级：新增可选字段 = 补丁版本；删除字段/改类型 = 主版本，需三端会签
- SSE 事件契约：新增事件类型必须先经前端忽略未知类型的容错测试（前端收到未知 `type` 时静默丢弃 + 计数上报，不崩溃）

### 8.3 「前端禁止直连平台」的测试强制（三重手段）

| 手段 | 实现 | 判定标准 |
|------|------|----------|
| 静态扫描（CI 门禁） | 扫描前端源码与构建产物中的平台域名/内网地址/IP 段黑名单；含日志上报、埋点、静态资源引用 | 命中数 = 0，否则合并阻断 |
| 出口代理强制（E2E） | E2E 环境所有客户端流量经代理，白名单仅含各自后端域名；平台域名配置为「可解析、可连通」以检测真实绕过行为 | 代理日志中来自前端的平台域名请求 = 0；出现即该用例失败 |
| 运行时 CSP + 审计 | 生产 CSP `connect-src` 仅允许各自后端域（复用主 SPEC §6.4 CSP 模式）；平台网关记录调用方来源（经后端签发的服务凭证），无凭证或凭证为前端类型的调用 100% 拒绝并告警 | 平台审计中「前端直连」事件 = 0；凭证校验拒绝路径纳入 §8.1 提供者测试 |

补充：该约束同时覆盖管理控制台前端；两个应用端后端调用平台必须携带各自的服务身份凭证，平台侧按凭证维度做限流与计量（与 §7.4 T2 组织限流联动），使「绕过自身后端」在计量侧也不可隐藏。
