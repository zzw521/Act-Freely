## 0. 需求背景与定位

**需求**：设计一个 agent 办公系统，分三层——Agent 平台（Backend-Only：agent、任务、知识、模型接入等基础能力）、用户端（Full-Stack：对话与推进任务）、管理控制台（Full-Stack：agent 管理、权限、审计与成本）。边界：两个应用端均依赖 Agent 平台；前端只允许依赖各自后端，不得直连平台。约束：DAU ~50K，峰值并发会话 ~2000，并行任务受上限控制；模型调用限流降级，token 成本受预算管控。

**定位裁决（TL-0）**：本系统是现有「通天办公」云端体系的**演进版本**，复用云端 SPEC 六组件（Auth/Sync/Runner/Gateway/Files/Admin）与主 SPEC 能力矩阵，聚焦差异与增量。桌面端（Tauri local-first 本体）定位为用户端的一种形态：本地能力 local-first 不变，云端能力经用户端 BFF 接入，密钥永不上云原则不变。

**总体结论**：三层需求不是替换云端 SPEC，而是三处结构性增量——（1）**组件重组**：Runner+Gateway 下沉为独立 Agent 平台（Backend-Only）；（2）**契约加层**：前端直连 `/api/v1` 改为经两个薄壳 BFF 转发（契约外壳保留）；（3）**能力补全**：知识服务、全局并发调度、预算硬控、平台运营视角、注入防御五项现有设计零覆盖。Phase A 可原样执行，Phase B 排期 6→8~9 周，Phase C 6→7~8 周。

## 1. 六大视角结果

### 1.1 产品专家（详见 experts/01-product.md）

**结论摘要**：北极星指标「周 Agent 交付任务数」，按 DAU 50K、人均 2.5 任务/日、一次完成率 85% 推导，GA+16 周目标周交付 ~74 万任务、D7 留存 ≥30%、组织付费转化 ≥5%、单任务成本 ≤¥0.3。MVP = 云端 Phase A 全量 + Phase B 核心闭环 + 平台抽离 P0（全局调度/三级配额/预算硬停）+ 控制台 P0。

**风险清单**（摘要）：

| 编号 | 风险 | 等级 |
|------|------|:----:|
| P-R1 | 知识能力现有设计完全缺失，范围与排期双失控 | 高 |
| P-R2 | 峰值容量与限流降级无量化设计 | 高 |
| P-R3 | 分层边界与云端 SPEC「契约复用」原则冲突 | 高 |
| P-R4 | 成本管控无量化基线（仅阈值告警） | 中 |
| P-R5 | 平台运营角色视角无任何承载 | 中 |
| P-R7 | 契约缺多租户维度（32 command 为单用户桌面设计） | 中 |
| P-R8 | 演进地基未就绪（Rust 侧仅 5/32 command 落地） | 中 |

**核心建议**（P0）：S1 Runner+Gateway 重组为独立平台服务；S2 平台三级配额与降级体系；S3 契约分层（`/api/v1` 保留 + `/admin/v1` + `/platform/internal`）；S4 桌面端 P0 验收后才启动平台改造；S5 预算三级硬停。

**待澄清**：token 成本承担模式（推荐双轨：平台补贴免费额度 + 组织按量付费）；DAU 口径（推荐全产品，Web 占比 Phase B ≥20%）；Phase A 与平台抽离顺序（推荐 A 先行、抽离与 B 并行）。

### 1.2 架构专家（详见 experts/02-architecture.md）

**结论摘要**：Auth/Files/Sync 复用为主，Runner/Gateway 升级为平台级服务，Admin 拆分为组织自服务与平台运营两套，知识服务与 Agent 注册为全新增量。四处硬缺口：Web 前端直连集群违反边界、知识能力无承载、Gateway 无预算台账、容量规划空白。容量估算：BFF 突发 1500 QPS、事件总线 ≥10K msg/s、Runner 峰值 500 并发（~250 vCPU）、PG 月增 ~150GB、对象存储月增 ~3TB。

**风险清单**（摘要）：

| 编号 | 风险 | 等级 |
|------|------|:----:|
| A-R01 | 前端直连云端集群与新边界冲突，三处返工 | 高 |
| A-R02 | 知识能力从零新建，工期与选型风险最高 | 高 |
| A-R03 | 预算管控权威缺失（无台账/预扣/硬停） | 高 |
| A-R04 | 容量规划空白（仅 5 项时延指标） | 高 |
| A-R05 | SSE 断线续传缺失（无 seq/Last-Event-ID） | 高 |
| A-R06 | Runner 池成本与冷启动（250 vCPU，冷启动 >5s 击穿 P95） | 高 |
| A-R07 | 依赖方向无机制保障（无服务间认证/网络分区） | 中 |
| A-R08 | 限流状态多实例不一致（本地令牌桶分裂） | 中 |
| A-R11 | 契约从单一来源裂变为三套，三向漂移 | 中 |

**核心建议**（P0）：A-01 用户端 BFF；A-02 平台 8 域能力清单 + 私有子网 + 服务凭据；A-03 任务编排集中化（租约 heartbeat 10s/租约 30s + Idempotency-Key）；A-04 SSE 可靠性契约（seq + 重放窗口 ≥10min）；A-05 预算台账（Gateway 单点权威，预扣+硬停）；A-06 容量规划基线。

**待澄清**：事件总线选型（推荐 Redis Streams）；预算单位（推荐 token+金额双台账）；控制台服务对象（推荐平台运营独立应用 + 组织自管理并入组织视角）。

### 1.3 业务专家（详见 experts/03-business.md）

**结论摘要**：主 SPEC 9 状态机为单机形态设计，云端化存在 5 处结构性缺口（无排队/预算暂停/任务级重试/取消/归档态）。给出 14 状态 + 1 子态云端状态机（35 条合法转移、9 个新字段）、14 个异常场景处置矩阵、4 类三方闭环及 11 项缺失环节、跨端裁决 R1-R4 与续接 C1-C4 规则。状态机扩展与预算-排队联动为 P0，须先于 Phase B 冻结。

**风险清单**（摘要）：

| 编号 | 风险 | 等级 |
|------|------|:----:|
| B-R1 | 无排队态，高峰 chat_submit 只能报错，Phase B 验收闭环必然破裂 | 高 |
| B-R2 | 预算管控只到告警未下沉任务状态，可能静默烧穿预算 | 高 |
| B-R3 | 任务层无重试态，85% 一次交付率云端难达成 | 高 |
| B-R4 | lease 租约机制完全缺失 | 高 |
| B-R5 | 用户离线后云端任务行为未定义 | 高 |
| B-R6 | 错误码缺 6 个云端必需码 | 中 |
| B-R7 | 三方闭环 11 项缺失集中在对账/补偿 | 中 |
| B-R8/R9 | pending_review 无 TTL / 取消语义缺失 | 中 |

**核心建议**（P0）：B1 状态机扩展 14 态 + 错误码补全；B2 lease 租约协议；B3 Gateway 预算闸门；B4 事件持久化 + seq 断点续传。

**待澄清**：四组 TTL 数值（推荐 pending_review 7 天 / budget_paused 24h / 事件存储 24h / 冲突版本 30 天，组织级可配）；手动重试 retry_count 不重置；预算组织级主闸门 + 成员软限额；reject 保留→done 以 REJECTED 区分；支付宽限 3 天。

### 1.4 运营专家（详见 experts/04-operations.md）

**结论摘要**：北极星「周有效完成任务数」（≥25 万/周），五层 18 项量化指标；七大运营抓手（模板任务激活、技能市场飞轮、定时任务留存为核心）。成本管控为最大增量：四级配额（组织/用户/agent/任务）+ 70/85/95/100% 四档预警 + 三级超限动作 + 预算熔断（¥30 万/月硬顶）。按 DAU 50K 估算月 token 成本 ¥28–40 万。最高风险：埋点与指标管道完全缺失，须 P0 先建。

**风险清单**（摘要）：

| 编号 | 风险 | 等级 |
|------|------|:----:|
| O-R1 | token 成本失控（免费层批量注册滥用可翻倍） | 高 |
| O-R2 | 埋点与指标管道缺失，所有目标无法度量 | 高 |
| O-R3 | 免费配额过紧伤害激活 | 中 |
| O-R8 | 降级动作拉低任务成功率反噬留存 | 中 |
| O-R6 | 双轨模型计量口径混淆 | 中 |
| O-R4/R5 | 技能市场供给不足 / 排行榜隐私争议 | 中 |

**核心建议**（P0）：O1 埋点与指标管道（走各端后端转发）；O2 四级配额 + 四档预警 + 三级动作；O3 成本看板。

**待澄清**：排行榜隐私口径（推荐仅成员级任务数/成功率聚合）；任务成功率判定方（推荐系统为主 + 用户点评为辅）；北极星「有效」口径（done + 24h 无回滚 + 无差评）；enterprise 档配额自定义。

### 1.5 安全专家（详见 experts/05-security.md）

**结论摘要**：现有安全基线建立在桌面 local-first 之上，云端化出现四类零覆盖攻击面：① RAG 检索内容与工具返回值成为提示词注入主通道（主 SPEC 威胁模型无注入项）；② agent 间消息信任边界失效；③ 平台服务间无认证与最小授权；④ 审计无防篡改/保留期。P0 增量：注入防御链、RAG 权限隔离、审计防篡改、服务间最小权限、平台网络不可达。

**风险清单**（摘要）：

| 编号 | 风险 | 等级 |
|------|------|:----:|
| S-R01 | RAG 检索内容注入 | 高 |
| S-R02 | 知识库检索无权限隔离（跨租户泄露） | 高 |
| S-R03 | 第三方工具返回值注入（Web 端 MCP 远端不可信） | 高 |
| S-R04 | agent 间消息注入与伪造 | 高 |
| S-R05 | 数据分级云端无强制点 | 高 |
| S-R06 | 审计日志可篡改 | 高 |
| S-R07 | 平台服务间无认证，单点突破横向扩散 | 高 |
| S-R08 | 前端绕过 BFF 直连平台无防御 | 高 |
| S-R09~15 | RBAC 矩阵缺失、硬开关通道不全、上传注入、PII 登记、留存合规、降级破坏分级、导出泄露 | 中 |

**核心建议**（P0）：SEC-A-01 五通道注入防御链（L1-L5 逐层验收）；SEC-A-02 RAG ACL 强制隔离；SEC-A-03 数据分级三个云端强制点 + `DATA_TIER_BLOCKED`；SEC-A-04 审计 append-only + 哈希链/WORM；SEC-A-05 服务间短时凭证 + scope 白名单；SEC-A-06 两端 API 硬隔离。

**待澄清**：知识库跨组织共享形态（推荐 Phase 1 仅组织私有）；控制台独立登录会话（推荐独立鉴权 + 二次验证）；出域硬开关是否禁同步上云（推荐是，零出域语义）。

### 1.6 测试专家（详见 experts/06-testing.md）

**结论摘要**：现有测试基线均为单机口径。验收按三层重分配：平台新增 4 项硬指标（2000 SSE/30min 断开率 0、并行上限 100% 生效、429 拒绝率 100%、预算硬停 ≤5s 误差 ≤±2%）；SSE 延迟拆双口径；平台可用性 99.5%→99.9%。LLM 非确定性用「结构断言 + 轨迹断言 + LLM-as-Judge」，黄金集 ≥120 条、回放 miss 即失败。压测 8 场景矩阵 + 10 个限流/预算专项。前端禁直连平台经 CI 静态扫描 + E2E 出口代理 + CSP/凭证审计三重强制。

**风险清单**（摘要）：

| 编号 | 风险 | 等级 |
|------|------|:----:|
| T-R1 | LLM 非确定性导致 E2E 大面积 flaky，放宽断言后漏检 | 高 |
| T-R2 | Mock 回放与真实模型失真（测试全绿、线上漂移） | 高 |
| T-R3 | 2000 并发 SSE 压测结论失真（压测机瓶颈/无背压仿真） | 高 |
| T-R4 | 限流/预算无专项验证，峰值下静默失效 | 高 |
| T-R5/R6 | 契约双层漂移无 CI 门禁 / 直连约束无测试强制 | 中 |
| T-R7 | 占位假实现混入 E2E 绿区 | 中 |
| T-R9 | 计量误差累积（流式中断/重试重复计费） | 中 |

**核心建议**（P0）：S1 三层验收指标冻结；S2 LLM 语义级回放（miss fail-fast）；S3 黄金用例集 + 行为断言框架；S4 压测基线先行（Phase B 上线门禁）；S5 限流/预算专项用例集。

**待澄清**：压测模型真实性（推荐默认 Mock + 上线前 200 并发真实联调）；控制台低压基线单列（50 并发、审计查询 P95<2s@100 万条）；云端回滚实现路径（推荐容器卷快照 + 产物版本化，验收线 ≥99% 不变）。

### R4 安全合规 vs 体验

| ADJ-R4-4 | 提示词注入拦截强度 | 安全五层防御 vs 体验延迟 | **分级处置**：高危硬阻断（`INJECTION_BLOCKED`）、中危标记 + 用户确认、低危仅记录；误报率目标 <1%（正常文本误拦 ≤2%）、拦截延迟 P95 <200ms、注入用例拦截率 ≥95% | 防御强度与体验量化平衡 |

## 4. MVP 建议

### 4.1 首版范围（MVP = Phase A 全量 + Phase B 核心 + 平台抽离 P0 + 控制台 P0 + 安全/测试 P0）

1. **账号与同步**（Phase A 原样，~4 周）：注册/登录、桌面端数据单向上云；未登录全功能可用；账号模型预埋组织字段。
2. **用户端 Web 闭环**（Phase B，8~9 周）：对话→计划审阅→执行→交付；附件/产物；任务排队反馈（位次透出）；降级/限流用户侧提示。契约沿用 `/api/v1` 外壳，经用户端薄壳 BFF 暴露（ADJ-R1-1）。
3. **Agent 平台 P0 面**：任务执行引擎（runtime-pool）、模型网关（托管 Key + 四级配额 + 降级链 + 预算台账）、全局并发调度（500/50/3 + 队列 1000）、Agent 注册表（预置 Agent）、计量管道、事件总线（Redis Streams）。
4. **云端任务语义 P0**：14 态状态机 + lease 租约 + SSE seq 重放 + 事件持久化 24h + 6 个新错误码——先于 Phase B 开工冻结。
5. **管理控制台 P0 面**（Phase C，7~8 周）：组织/成员管理（RBAC 矩阵）、预置 Agent 管理（启停/模型绑定/配额）、用量与配额（70/85/95/100% 四档预警）、审计检索+导出（哈希为主 + 高危全文 90 天）、成本看板（双轨分列 + 趋势预测 + 四维下钻）、出域硬开关（扩通道）。
6. **安全 P0 面**：五通道注入防御链（分级处置）、RAG ACL 隔离（随知识 Phase C）、数据分级三强制点、审计防篡改、服务间最小权限、平台网络不可达。
7. **测试 P0 面**：三层验收指标冻结、LLM 语义级回放、黄金集 ≥120 条、压测基线先行（Phase B 上线门禁）、限流/预算专项 T1-T10。
8. **验收硬指标**：峰值 2000 会话不雪崩（SSE 断开率 = 0）、超限 100% 走降级/排队、预算 100% 硬停（≤5s、误差 ≤±2%）、平台可用性 99.9%。
