# 未实现与未验证清单（2026-10-20）

> 与 [能力台账-2026-10-19.md](./能力台账-2026-10-19.md) 同一判定标准：用户能触发 → 真正执行 → 结果可见。
> 只把配置写进库/盘、模型或引擎不消费的，不算实现；界面已如实禁用或标注「尚未接入」的，也不冒充能力。

- 这些 Agent 都在**本机同一进程**里；跨用户/跨电脑的任务交接走第 10 批的项目协作，但不改变子 Agent 的本机进程边界，也没有自动消息中继或 A2A/ACP 互操作。
- 子 Agent 不继承父 Agent 的对话历史、意识文件与附件，只拿到总目标、自己的任务说明、启用技能与同一套执行约束；信息不足时必须在汇报里说明缺口。

### 第 5 批：任务检查点 / 断点续跑（2026-10-22）

| 缺口 | 现在的真实链路 | 验证 |
| --- | --- | --- |
| 任务中断后只能从头再来 | 每次真实模型调用前把 Agent 记忆、工具台账与文件基线快照进 `TaskCheckpoint`；失败/取消/中断收尾时 `resumable=true`，`checkpoint` 事件先于 `done` 下发。中断收尾会把快照、副作用台账、runId 与会话上下文写入 `~/.tongtianwork/checkpoints/{sha256(taskId)}.json`（原子替换、版本号、7 天 TTL），引擎重启后仍能恢复 | `tests/integration/engine_checkpoint_selftest.py`、Rust `bridge::sse` 单测 |
| 恢复会重复写文件 / 重复调外部服务 | 副作用工具按 `sha256(工具名 + 规范化入参)` 记台账（写盘、生成 PPT、子 Agent 派发等，含 write/create/send/run 等关键词的 MCP 工具同判定）；恢复时只跳过**上一轮 run** 的同签名调用，命中后返回缓存结果并留下可见的「已跳过重复执行」说明；同一轮内的重复调用照常执行。跨进程恢复会沿用落盘的 `runId`，旧台账不会被误当成新一轮 | `engine_checkpoint_selftest.py`（恢复前手改文件，恢复后文件保持人工修改，证明未被覆盖） |
| 没有恢复入口 | 工作台在检查点可恢复时显示「从检查点继续」胶囊按钮，条件为 `resumable=true` + 检查点属于当前任务 + 任务未在跑；点击走 `chat:review action=resume`，同一 taskId 重跑，不新增对话轮次。Rust 只允许 done/failed/cancelled 续跑；启动失败回到原状态并下发 `CHECKPOINT_RESUME_FAILED`，不把可重试的中断误标成失败 | `tests/unit/workbench/checkpoint-resume.test.ts`、Rust `bridge::sse` 单测 |
| 恢复后丢上下文 / 丢产物 | 恢复时排除末尾未回答的用户消息，用目标 / runtime / 附件重新组装本轮提示并附加 `[断点续跑]` 要求；复用中断前的文件基线，中断前已产出的文件仍进入 `deliver` | 同上（E2E 断言恢复消息、`restoredMessages`、产物列表与模型调用次数） |

同批边界（不做假承诺）：

- 检查点收尾落盘（`scope:"disk"`）；**隐私模式不写盘**，正常完成会删除该任务的文件，超过 7 天或内容超过上限都会明确拒绝而不是截断后假装完整。
- 落盘内容不含密钥：`apiKey`、MCP 环境变量、Hook 网关地址与 token 都不进文件；恢复时桌面版按 `modelId` 重新解析模型与 runtime，浏览器直连按 `models.json` 解析。附件图片超过体积预算时会剔除图片正文并记录 `attachmentsMediaOmitted`，恢复提示里如实说明图片不会重发。
- 写盘失败会降级为 `scope:"same-process"`，`diskError` 与「仅当前引擎进程内有效」的说明一起下发，不把失败伪装成已持久化。
- 刷新/重启后的入口由 `POST /api/chat/checkpoint/query`（Rust `chat_checkpoint_query`）按最后一轮 taskId 批量取回；查询只返回摘要，不含会话正文。运行中的任务查询结果标记 `running=true` 且不可续跑。
- 跨机器恢复仍不支持：快照不包含凭据与工作目录迁移方式，不能只搬文件。
- Mock 通道没有真实检查点，resume 明确回报 `CHECKPOINT_UNAVAILABLE`，不伪造恢复成功。
- 恢复点是「最近一次模型调用前」；该次调用已经产生但尚未记账的副作用无法回滚，幂等只覆盖上一轮已记录成功的工具调用。
- 真实模型中断后续跑尚未实机验证（当前用脚本化模型验证整条接线，含模拟引擎重启后的跨进程恢复）。

### 第 6 批：受控命令执行与联网获取（2026-10-22）

| 缺口 | 现在的真实链路 | 验证 |
| --- | --- | --- |
| Agent 不能执行命令或上网 | 工作区沙箱策略新增四项显式授权（`execEnabled` / `execAllowlist` / `networkEnabled` / `networkAllowlist`），默认关闭。引擎只在「已开启且白名单非空」时注册 `run_command` / `fetch_url`；未授权时工具与 system prompt 同时缺席，原因作为可见说明下发。`run_command` 只接受白名单裸命令名，argv 方式执行（`shell=False`），工作目录固定为任务目录，超时 1–120s、输出 8000 字符上限，子进程环境变量按白名单裁剪（API Key 等不进子进程）。`fetch_url` 只接受 http/https 与精确主机白名单，DNS 解析结果必须全部是公网地址（本机/内网/链路本地/元数据拒绝），重定向逐跳复核（≤3 跳），非文本拒绝，2MB / 20000 字符双重截断 | `tests/integration/engine_tool_grants_selftest.py`、`tests/unit/security/sandbox-grants-contract.test.ts` |
| 执行/联网没有审计 | 每次真实调用（成功/失败/超时/拒绝）发 `tool_audit`；Rust 按工具名归一为 `exec_run` / `network_fetch` 动作码并落库，拒绝/失败/超时记 warning。审计 target 对 URL 去掉用户信息、查询串与片段，命令只记命令名与参数个数，参数原文不入库（统一走审计脱敏入口） | Rust `bridge::agent` 单测、`sandbox-grants-contract` |
| 授权开关容易被误解为「点了就生效」 | `/security` 沙箱策略页新增开关与白名单编辑；空白名单拒绝保存；首次开启需二次确认并列出将被授予的命令/主机与风险；浏览器预览通道禁用开关并说明策略不下发引擎 | `sandbox-grants-contract`；桌面版点击与真实模型工具调用尚未实机验证 |

同批边界（不做假承诺）：

- **浏览器自动化在本批仍未实现**（第 12 批已补齐，见该批）：本批只做「受控命令执行 + HTTP 文本获取」，不把 `fetch_url` 冒充浏览器；受控浏览器是单列授权、独立 profile 与页面级审计，不能复用 `fetch_url` 的实现。
- 没有操作系统级沙箱：命令以当前用户身份运行，白名单只限制命令名，不限制命令本身的行为。把 `python` / `node` 这类解释器加入白名单等于允许执行任意脚本，确认框已明说。
- 联网只做单次 GET 的文本读取，不执行页面脚本、不携带登录态/Cookie、不自动重试。
- 子 Agent 不继承执行/联网授权：只有父 Agent 拿到这两个工具，避免派发出去的子任务绕过用户对主任务的授权。
- 桌面版真实点击授权保存、真实厂商模型下主动调用工具的行为尚未实机验证。
