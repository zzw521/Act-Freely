# 通天办公能力对账台账（2026-10-19）

> 范围：`tongtian-tauri` 渲染层、Rust 壳（`src-tauri/src`）、Python 引擎（`engine/server.py`）。
> 方法：以 Rust `generate_handler!` 注册表、前端 `IPC_CHANNELS` / `tauriAPI` 路由、引擎 HTTP 路由与 `build_agent` 运行时消费三端交叉核对；每条能力给出代码位置，均可复查。
> 判定只看「用户能否触发 → 是否真实执行 → 结果是否可见」，不看页面是否存在、数据库是否有表。

> **2026-10-22 更新**：本台账是 2026-10-19 的历史快照，下面的 command/channel 计数与「只到配置层」结论不再代表当前状态。此后已按批次补齐执行面：附件正文、技能/套件指令、意识、MCP 工具、Hooks、子 Agent、检查点续跑、受控命令与联网、电脑操控、受控浏览器 AI+、本地知识库、在线市场、MCP OAuth、跨用户项目协作。逐项当前状态与边界见 [未实现清单-2026-10-20.md](./未实现清单-2026-10-20.md) 第〇节第 1–12 批。

## 一、结论摘要

| 指标 | 数值 |
| --- | --- |
| Rust 注册 command | 103 |
| 前端 IPC channel | 99（99/99 有处理器） |
| 引擎 HTTP 路由 | 28 |
| 全链路可用 | 57 |
| 管理面（已落库/落盘，但 Agent 运行时不用） | 25 |
| 部分可用 | 10（IM 7 + 附件暂存 1 + 沙箱策略 2） |
| 占位/死代码/不可达 | 5 |

| 仅内部调用 | 1 |

一句话结论：**聊天闭环、模型、文件、调度、认证、审计、归档是真的；技能 / 套件 / MCP / 意识 / Hooks / 电脑操控目前只到「配置与管理」层，没有进入 Agent 的执行面。** 另外，引擎实际交给模型的工具只有 3 个文件工具（`engine/server.py:947-949`），没有命令执行、浏览器或 MCP 工具；附件虽然能上传，但 `/api/chat` 没有消费 `attachments`。

状态口径：

| 状态 | 含义 |
| --- | --- |
| 全链路 | UI 可触发，Rust/引擎真实执行，结果可见 |
| 管理面 | 配置、文件、SQLite 都是真的，但 Agent 的 prompt / tool / hook 不消费 |
| 部分 | 主链路可用，但有明确缺口（如 IM 五个通道实现了三个、沙箱策略只执行了一部分） |
| 占位 | 无真实后端或应用内不可达 |
| 未接线 | 后端真实，但前端没有消费入口 |
| 内部 | 不作为用户能力，由其他命令内部调用 |

## 四、整改顺序与验收标准

### 可复用的现有资产

- 仓库内已有一棵 QwenPaw 派生的完整 Python 代码树 `tongtian-tauri/src/agent/`，包含 `agents/skill_system`、`agents/memory`、`security/tool_guard`、`sandbox` 等模块；当前 Tauri 运行链路未 import 它（引擎只 import `agentscope`，全仓未发现 `src.agent` 或 `agent` 包的引用）。它不改变上面的判定，但可以作为 P0「技能接入 / 记忆接入 / 工具守卫 / 沙箱」最省力的复用来源；接入前需裁剪其配置与依赖。该目录已在 `NOTICE` 中按 Apache-2.0 归属声明。
- `mcp/mod.rs:552` 已有真实 JSON-RPC 握手，可在其上加 `tools/call`，不需要另写连接层。
- `engine/server.py:859-950` 的工具注册与路径守卫可直接扩展为统一 ToolRegistry。

### P0：把「产品承诺」接到执行面

1. **统一 Agent 执行面（技能 / 套件 / MCP / 意识）**
   - 在 `build_agent` 组装 prompt：读取意识 `SOUL.md` / `USER_PROFILE.md` / `MEMORY.md`（尊重 `mode` / `autoMemory`）；扫描启用的 `skills/*/SKILL.md` 注入摘要或注册为工具；把 MCP 工具通过 `tools/call` 注册进 `Toolkit`。
   - 验收：安装一个测试技能后，对话请求的 system prompt 包含其内容；一个本地 MCP echo 工具能被模型真实调用；修改意识文件后下一轮回答受其影响；契约测试锁定「安装/启停 → 运行时可消费」。
2. **附件进入模型**
   - Rust 暂存后，由 Rust 或引擎把 `AttachmentMeta` 转成模型消息：文本类用现有 Office/PDF 抽取（`file/office.rs`），图片按模型能力传 image block；不能只传路径。
   - 验收：上传 `.docx` 后提问，模型能引用正文；上传图片后视觉模型能描述内容；抽取失败时明确报错，不静默忽略。
3. **Hooks 生命周期**
   - 在 Rust bridge 或引擎执行链路触发 12 类事件；`PreToolUse` 支持阻断；读取 `hooks_get` 的配置，和 `hooks_test` 共用同一个 `run_command`。
   - 验收：配置 `PreToolUse` 拦截 `write_text_file` 后，工具调用被拒且事件可在界面看到。
4. **诚实性收口**
   - 电脑操控在补执行器前改为「策略预览（尚未接入）」或下线；连接器中心要么挂路由并补 OAuth，要么删除；专家套件市场真实模式空态要明确「无远端市场」；清理死页面。
