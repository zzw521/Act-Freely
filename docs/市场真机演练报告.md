## 一、为什么要真服务端

`src-tauri/src/market` 原有的全部用例都跑在本机 `serve_n_on` 假服务上：它们能钉住客户端的规则（撤销闸门、哈希校验、回环放行、无覆盖安装），却钉不住**服务端索引适配层给的形状客户端到底收不收**。这两处粒度不同， mock 是自己写给自己的，永远测不出来：

| 粒度差异 | 服务端存储 | 桌面端要的东西 | 处置 |
|---|---|---|---|
| 技能产物 | zip 包 | zip 里那份 `SKILL.md` 的**字节本身**，索引 `sha256` 必须是那份字节的摘要 | 适配层真实解包取文件（`_skill_md_of`），不给 zip 摘要 |
| 撤销清单 | `/api/v1/revoked` 分页（20/页，带 total） | `revokedUrl` 只拉**一次**，要扁平裸数组 | 新增 `/api/v1/desktop/revoked.json` 不分页（上限 500） |

## 四、独立复核（不依赖客户端，直接打 HTTP）

| 结论 | 检查 | 实测 |
|---|---|---|
| ✅ | 索引顶层形状（技能/套件同构） | 键集恰为 `{publishers, revokedUrl, revokedVersions, signaturePolicy, skills\|suites}`；`signaturePolicy="optional"`、`publishers=[]`、`revokedUrl=http://127.0.0.1:8731/api/v1/desktop/revoked.json` |
| ✅ | 技能摘要口径 = SKILL.md 字节 | 产物前 4 字节 `---\n`（不是 `PK\x03\x04`）；`sha256=0e04d809fd5bb6be…7510a` 与落盘字节摘要一致；`sizeBytes=160` == 实际字节数 |
| ✅ | 套件摘要口径 = zip 包 | 产物前 4 字节 `PK\x03\x04`；`sizeBytes=688` == 实际字节数；`sha256=62a852af3718…` 与包摘要一致 |
| ✅ | 产物响应头可缓存且自带摘要 | `X-Checksum-Sha256`、`ETag="0e04d8…"`、`Cache-Control: public, max-age=31536000, immutable`、`Content-Type: text/markdown; charset=utf-8` |
| ✅ | 撤销清单一次拉全（裸数组） | `[{skill, drill-gone, 1.0.0, 演练全撤}, {skill, drill-revoked, 1.1.0, 演练撤销：正文有误}]` |
| ✅ | 已撤版本的产物直接拒发，条目 ID 非法另有码 | `drill-gone@1.0.0/SKILL.md → 410`、`drill-revoked@1.1.0/SKILL.md → 410`、不存在条目 → 404 |
| ⚠️ | 控制面与桌面索引**故意不一致** | 全撤的 `drill-gone` 在控制面 `GET /api/v1/skills/drill-gone` 仍 200（条目存在、版本全撤），桌面索引里却不出现。这是设计：管理台要看得见撤了什么，桌面端不该点一次必败的下载 |

## 五、本轮发现并修掉的缺陷

| 层 | 现象 | 根因 | 处置 |
|---|---|---|---|
| **产品缺陷**（服务端适配层） | `GET /api/v1/desktop/revoked.json` 返回 404 `MARKET_NOT_FOUND` | 适配层原来用通配路由 `/api/v1/desktop/{plural}.json`，`{plural}` 吃到 `"revoked"` → `type_of_plural` 返回 None。**真机上等于整条撤销链失效**：客户端只拉一次撤销清单，拉不到就只剩索引自带的声明 | 删通配，改两条显式路由 `/api/v1/desktop/skills.json`、`/api/v1/desktop/suites.json` + 共享 `_build_index`；`main.py` 里适配层必须先于市场通配路由注册（`/api/v1/{plural}/{item_id}` 会把两段的 `revoked.json` 当成条目 ID）。契约测试 `test_route_precedence` 把这两条吞法都钉住（`mcps.json`/`nonsense.json` 要 404 且**不是** `INVALID_ITEM_ID`） |
| 产品缺陷（同上，次生） | 技能的 `sizeBytes` 报的是 zip 大小 | 客户端按类型上限校验（技能 512KB 是**正文**上限），语义给错会误拒条目 | 技能报 SKILL.md 字节数、套件报包大小；版本段一律 percent-encode |
| 演练台缺陷 | 首轮演练在 `✓ 发布者登录` 处崩 `UnicodeEncodeError: 'gbk' codec can't encode '\u2713'` | Windows 控制台/重定向默认 GBK，`✓` 编不出来 | `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`；顺手删掉未用的 `signal/socket` 导入 |
| 演练台缺陷 | 发第二版报 400 `VERSION_REQUIRED` | 演练正文没有 front-matter `version:`，服务端 `_resolve_version` 对新版本既无声明也无显式版本就拒 | multipart 字段补 `version`；在代码里注明为什么必须给 |

后两条是**演练台自己的 bug，不是产品 bug**，但都是真机才暴露出来的——这正是做演练的意义。

## 六、签名策略：如实降级

桌面端 `signaturePolicy` 支持 required/optional。服务端目前**没有发布方内容签名密钥**（`keys.py` 那对 RS256 是网关登录令牌用的，不是内容签名），所以适配层固定 `optional` 且不写 `publishers`。客户端据此给出的结论是字面量「未签名（索引未强制签名）」，演练第 ⑦ 步把它钉成了断言——**没有假装验签**。要做真签名，需要发布者密钥体系与索引侧签名，属 D-07 后续。

## 七、未覆盖的边界（别把这份报告读成「市场链路已全验」）

- 只打了**回环 http**：远端索引必须 HTTPS、禁止指向 localhost 那几条闸门，由既有 mock 用例钉着，本演练没有对真远端跑过。
- 真实第三方市场索引（非本项目服务端）没有接入演练。
- Docker / 反代 / TLS 终结未参与（本机 Docker 不可用）。
- 并发发布与撤销竞态、500 条上限的截断行为，未在真机上量过。
