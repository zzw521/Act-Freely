## 3. 状态明细（D-09 一节下新增）

**状态**：**进行中（2026-11-03）**——引擎侧混合检索的**离线半边**落地：向量召回、混合打分、

（`#164` 注册面未交棒）。

**进展（2026-11-03，W2 #137）**：

- **嵌入供应商三档，离线优先**：`sentence-transformers`（需 `TT_EMBEDDING_LOCAL_MODEL`，装包即用，
  走本机模型缓存不联网）→ OpenAI 兼容 `/v1/embeddings`（需 `TT_EMBEDDING_BASE_URL` +
  `TT_EMBEDDING_MODEL`，密钥**只**从 `TT_EMBEDDING_API_KEY` 读，不写配置、不回显）→
  内置特征散列词面向量（零依赖、跨进程可复现、512 维、L2 归一）。`resolve_provider` 选中的
  供应商只要不是语义模型就把「这不是语义召回」追加进说明；`TT_KNOWLEDGE_RETRIEVAL=lexical/off/none`
  时直接不返回供应商并说明「按配置关闭向量召回」。
- **向量表与词法表同一个 `.index.sqlite`**：`vec_rows(doc, seq, provider, vec)` + `vec_meta`。
  换嵌入来源 ⇒ **整表重建**（不同模型的余弦不可比，混用就是假排序）；正文段落被删 ⇒
  **清孤儿向量**（本刀第一版没清，真实跑出「正文已经不存在的文档仍以 0.87 分命中」的幽灵结果，
  已修并加回归）。向量指向空正文的段落一律不进结果——不许带空正文冒充命中。
  待建段数超过 `MAX_VECTOR_CHUNKS`（20000）时**如实拒建**并退回词法，不悄悄少建。
- **混合打分**：`LEXICAL/COVERAGE/TITLE` 三档权重沿用改造前取值不动，`VECTOR_WEIGHT=0.15`、
  `EXPANSION_WEIGHT=0.10` 各加一档；「同一文档最多两段」的老规则继续负责来源多样性
  （**刻意没有另造 MMR**——它与这条上限重复，且对纯词法候选（无向量）是空转，属伪功能）。
  每条命中带 `retrieval` ∈ {`lexical`, `vector`, `hybrid`}，用户与模型能看见这一段是怎么来的。
- **库内共现扩展**：`expansion_terms` 只从当前候选正文里取与查询词高频共现的双字以上词补进打分，
  候选不足两段 / 命中不足两篇 / 查询词全是单字时**宁可不扩展**。扩展了什么必须写进说明
  （「检索词按库内共现自动扩展：…」）。
- **扫描件状态**：`docs/` 里有原件而 `text/` 抽不出正文（缺文件或有效字符 < 8）⇒ 点名是哪几篇、
  说明「本机未做 OCR、这几篇检索不到」。库名用运行时给的显示名，不是目录名。
- **降级不是失败**：嵌入调用抛异常（含上游 503）⇒ 该轮退回词法结果、结果照常返回、
  原因带进 notes（`embeddings`/`嵌入`/`退回词法召回` 字样可断言）。索引文件损坏同样不影响任务本身。
