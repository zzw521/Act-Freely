## 2. 口径句（供「更新N」条目使用，编号由 W4 合并时定）

> **① 落地范围（D-30，W5 #139）**：定时调度在原有「每小时 / 每天 / 每周 / 每月 1 日」之外
> 补两种频率——`interval`（每 N 分钟，1 分钟～一周，句子里的「每 N 小时 / 每 N 天」都换算成
> 分钟步长，**无固定时刻锚点、从上次执行起算**）与 `once`（绝对时刻执行一次，到点自动停用）。
> 存量库靠 **V19** 只追加 `interval_minutes` / `run_at_ms` 两列（只加列、不动索引、不重算任何
> 存量行的 `next_run_at_ms`），老任务两列为 NULL 而不是 0——0 会被读成「每 0 分钟」这种
> 既非法又看起来像配置的值。**② 解析覆盖面**：「今天 / 明天 / 后天 / 大后天 / 下周X」、
> `yyyy-mm-dd`、中文「11 月 5 日」「3 月 8 日」、缺省年份（本年已过点顺延一年并**如实说明**）；
> 写了年份却已过期、或 2 月 30 日这类不存在的日期一律拒绝，不排一个永远不会到点的任务；
> 「每 N 周」两种口径都不成立，**如实拒**而不是猜成每周或 7 天。**③ 先预览再确认**：
> 解析结果只给一句中文预览（`每 2 小时执行一次` / `2026-03-06 09:00 执行一次（本地时间，确认后落库）`），
> 界面**不再把解析结果直接写进表单**，用户点「确认使用」才回填；周期说法撞上具体日期时
> **保留周期**并把日期回显在提示里——把周期任务悄悄改成只跑一次比忽略那个日期更危险。
> **④ 时区口径（跨语言，必须一起读）**：Rust 侧无 chrono，`time_of_day` 与日期展开一律按
> **UTC 日**；界面按**本地**呈现与录入，`runDateRelative` 标记「今天/明天/下周X」这类相对说法，
> 渲染层用 `reanchorRelativeRunDate` 按「本地日 − UTC 日」的差平移天数，配合预览确认消化
> UTC+8 用户在 00:00–07:59 说「明天」的差一天风险。**⑤ 落库字段**：`interval` 的
> `time_of_day` 恒为 `00:00`，`once` 的绝对时刻存 `run_at_ms`（UTC 毫秒）而不是把时刻塞进
> `time_of_day`，两条通道读同一份事实。**⑥ 边界**：只改 `task::schedule` / `store::migrate` /
> 渲染层，**未碰** `lib.rs`、`contracts.ts`、`engine/server.py`——新字段靠 serde `Option`
> 向后兼容与 `contracts_connect.ts` 扩展类型落地；`SCHEDULE_UNSUPPORTED_FREQ` 等五处错误文案
> 随新能力更新但**保留被契约测试钉住的中文子串**（「每小时」「24 小时制」「正在执行中」）。
> **⑦ 零依赖、零新端点、零新工具名、零副作用名单变更**（§5 只需 W4 处理契约回收请求）。

vitest `tests/unit/schedule` 84 项、全量 vitest 106 文件 / 2125 条全绿、`tsc --noEmit` 退出码 0）；
「到点自动执行 + 一次性跑完自动停用」这条只有 Rust 扫描链路覆盖，**真机未验收**。

**进展（2026-11-04，W5 #139）**：

- **间隔不从时刻派生**：`interval` 存的是分钟步长，触发点 = 上次执行 + 步长；句子里出现的
  「上午 9 点」只参与名称清洗与说明，绝不写进 `time_of_day`，否则界面会显示一个并不会按它
  触发的时刻（这是台账里「复用 hourly 表达间隔」那条被明确否决的原因）。
- **一次性任务不会被复活**：`next_run_at_ms_full` 对过点的 once 返回 `None`（不排期），
  而**不是**退回「每天」——一次任务变永久任务是最坏的一种错。手工「立即执行」走 `finish_run`，
  不消费原定时刻，到点仍会再跑一次；自动停用只写在 `advance_next`（调度器触发前）这一处。
- **换频率即清配置**：改频率或改字段任一发生就重算 `interval_minutes` / `run_at_ms`，
  换成别的频率时置 NULL（Rust 与 TS 台账同口径，用例
  `test_update_between_interval_and_recurring_clears_fields`）。留着旧步长会让界面显示一个
  并不生效的配置。
- **两条通道同一套算法**：`schedule-local.ts`（Mock / 浏览器直连引擎的本地台账）把
  daily/weekly/monthly/hourly/interval/once 六种下次执行时间与中文解析全部按 Rust 同构重写，
  `npx vitest run tests/unit/schedule` 与 Rust 用例逐条对齐；跨语言一致性由
  `tests/unit/schedule/update-contract.test.ts` 钉住 Rust 结构体字段、`pub fn update(store,&req,now_ms)`
  签名与 UPDATE 语句文本。
- **禁用即清空排期，重新启用按当前时刻重算**；一次性任务原定时刻已过时，启用会报
  `SCHEDULE_INVALID_TIME: 一次性任务「X」原定执行时间已过，请先改日期再启用`，
  而不是排一个永远不会到点的任务。

**剩余**：见 §4。
