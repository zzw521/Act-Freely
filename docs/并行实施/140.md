## 3. 状态明细（D-13 一节下新增）

**现状（改造后）**：快照流水线与浏览器上下文接力判定都落在 workspace 车道
（`engine/routes_workspace.py`，由 #164 的 `/api/snapshot` 前缀声明覆盖），界面有面板与页面壳。
不发生的事也要写清楚：

- **本车道不截屏**。`/api/snapshot/capture` 收的是调用方交上来的采集物（文本 / base64 图）；
  真实前台应用识别、OS 屏幕捕获、全局快捷键都在桌面壳里，IPC 未接线 ⇒ **真机采集未验收**
  （这条由 `snapshot_runtime.status()["unverified"]` 机器可读地带着，界面只做转述）。
- **正文只活在引擎进程内存里**：不落盘、不进审计、不进日志；引擎重启或超过 TTL 即消失。
  渲染层同样不留副本（`snapshot-api.ts` 里无持久层、无 `console.log`，测试按源码钉）。
- **图片无法本地检测**：勾选「带上截图」后由确认人承担分级判断，界面把这句话显示出来。
- **`forceLocal` 只做标注**：分级判到机密会带 `forceLocal: true`，但真正「只走本地模型」那一段
  不经过本模块——「机密不上送」这条闸只覆盖快照这条入口。
- **模型不能自己触发快照**：`snapshot_*` 两模块没有注册成任何工具，只有人（或调用方）经
  `/api/snapshot/*` 递东西进来；这一族对远程身份整条 403（`WS_DESKTOP_ONLY`，理由用的是
  snapshot 那一族自己的那一句，不共用后端清单那句——约束 B）。
- **待确认清单名实一致**：`/api/snapshot/pending` 默认只列待确认，要已确认/已取消/已过期的
  墓碑得显式 `status=all`；清单只回元数据，「列表不是预览」写在回话里。

**本刀改到的引擎侧缺陷**（都是先有实现、被自测抓出来的，不是顺手重构）：

1. `session_view` 早退时只回半套键 ⇒ 无 runtime 的授权请求 `KeyError: 'profileDir'`（补齐键集）。
2. `_host_from_text` 把 `javascript:alert(1)` 当成一个「域名」收下，回话还说「已授权 1 个域名」——
   假账；改成协议/路径/查询串/空格/冒号一律拒，其余统一走 `host_of`。
3. `decide` 复用 `grant` 时的策略关闭文案 ⇒ 十类拒绝只有九句；拆成各说各的（同一 `code` 不同句子）。
4. `_brief` 省略号没计入预算，返回 `limit + 1` 字（两模块各一处）。
5. 已取消的草稿 `confirm` 回 409、`preview` 静默回一份空正文行 ⇒ 都改 404，正文不再假装存在。
6. 幽灵码：`SNAPSHOT_NOT_PENDING` / `SNAPSHOT_DESKTOP_ONLY` / `RELAY_DESKTOP_ONLY` 在
   `status()["codes"]` 里被宣称却没人发 ⇒ 删；域名超限借用了 `RELAY_TAB_LIMIT` ⇒ 新
   `RELAY_HOST_LIMIT`；`want` 给错借用了「没授权」（403）⇒ 新 `RELAY_WANT_INVALID`（400）。
7. `/api/snapshot/pending` 名字叫 pending、实际全量 ⇒ 默认只列待确认 + `statusFilter` 回话。
8. `routes_workspace.py` 里 `READ_ONLY_PATHS` 定义了两遍 ⇒ 删一份，留指针注释。
9. `_snapshot_gate` 直接借后端那族的 403 句子（说桶名/SSH 主机）⇒ 拆成 `DESKTOP_ONLY_REASONS`
   按族取句，快照族那句点名「屏幕上的正文、截图与受控浏览器的域名清单」。
10. `decisions()` 空页时 `note` 为空字符串 ⇒ 区分「审计里还没有任何决策」与
    「这一页没有条目（过滤后为空或 offset 超总数）」。
11. 界面读侧一条**口径**（不是缺陷）：结论码**不进** `src/shared/error-messages.ts` 映射表，
    `failText` 优先用 `SnapshotApiError.message`（= 引擎原句）——映射表会把「为什么被拦」换成通用文案。

**界面镜像与引擎回话的逐键对齐**（§9 那节抓到的，全部是**拿真回话探针**跑出来的，不是照着类型猜的）：

| 引擎实际发的键 | TS 镜像原先的样子 | 后果（如果不钉） |
| --- | --- | --- |
| 命中项键名是 `kind` | 镜像写成 `type`（那是 Rust `classify.rs` 那一族的键名） | 界面每一张发现卡都显示空白 |
| 标签页行是 `host`（**只有域名**） | 镜像写成 `url` | 界面去读一个引擎从不发的键；而且「令牌不进接力现场」这条口径在界面上失去依据 |
| 撤销后的授权带 `revokeNote` | 镜像没这个键 | 界面只能说「已撤销」，说不出是谁、为什么撤的 |
| 快照账与接力账**字段集不同** | 共用一个 `DecisionRow` | 接力账的 `allowed`/`code`/`host` 与快照账的 `ok`/`draftId`/`sensitivity` 互相冒充，一半栏位永远空白 ⇒ 拆成 `SnapshotDecisionRow` / `RelayDecisionRow` |
| 采集回话顶层带 `ok` | `SnapshotPreview` 没这个键 | 界面读 `undefined`，「成没成」只能靠 HTTP 码猜 |
| 取消回话退回**整条草稿行** + 销毁计数 | `SnapshotCancelResult` 只镜像四个键 | 界面取消后要再拉一次清单才能改这一行状态（两次读之间清单还可能变） |

对齐方向是**双向**的：引擎发了而镜像没有 ⇒ 界面读到 `undefined`；镜像声明了而引擎从不发 ⇒ 那一栏永远空白。
两个方向各一条 `^[PASS]`，加「客户端返回类型直接引用共享接口」五条，都在 §9。
探针第一次跑就崩在 `AttributeError: 'SnapshotDraft' object has no attribute 'keys'`（`capture()` 回的是草稿对象不是行），
第二次崩在猜错的 runtime 键名上（`session_view` 要的是 `browserUse` 那一块）——两次都不是产品缺陷，
但**都记在这里**：这一节的值恰好在于它是拿真回话喂出来的，猜的形状一律不算。
