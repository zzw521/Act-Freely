## 2. 口径句（供「更新N」条目使用，编号由 W4 合并时定）

> **② 落地（D-37 服务端半边，本批次 W1 #142）**：新增 `tongtian-server/app/cli.py` 与
> `tongtian-server/tests/test_cli.py`——`python -m app.cli` 成为服务端**唯一**的无头管理面，
> 32 条命令分五组（`users` / `depts` / `tiers` / `audit` / `backup`）加四条单条命令
> （`health` / `serve` / `doctor` / `whoami`），全部只消费**已有**端点，**零新端点、零新表、零 `ALTER`、零新依赖**。
> 三条口径是这一刀真正的产出：**⑴ 机器面稳定**——一次调用一个 JSON 对象，固定
> `ok/contractVersion/command/data/problems/exitCode` 六键，退出码 0 成功 / 1 操作失败 / 2 用法错误，
> **用法错误也走同一个信封**（自定义 `_Parser.error()` 把 argparse 的退出改成 `UsageError`），
> 否则脚本只会在 stderr 里读到一段人类可读的 usage 而拿不到原因；**⑵ 凭据只走环境变量**——
> `TT_SERVER_TOKEN` 或 `TT_SERVER_ADMIN_EMAIL + TT_SERVER_ADMIN_PASSWORD`，
> `--token/--password/--authorization/--secret/--bearer` 五个名字**在解析参数之前**就被拒且**不回显被拒的值**，
> URL 里带凭据/非 http(s)/带查询串同样拒；收尾对全部捕获流与落盘文件做**凭据泄漏总扫**
> （口令、访问令牌、`Bearer `、JWT 密钥、裸栈七项），`audit anchor-create` 的签名串**默认不打**
> （`--print-signature` 才给：签名 + 库文件同时外泄等于把伪造材料寄出去）；
> **⑶ 本地面不假设服务在跑**——`doctor` / `backup` / `serve` 一次 HTTP 都不发，
> `doctor` 以 `file:...?mode=ro` 只读打开数据根，并新增 `keys.peek_keys()` / `keys.peek_store()`
> 两个**只读**入口：原来那里调的是 `key_store()`，它会 `mkdir` + 在空目录里**生成密钥对** +
> 到期就**轮换**——一次「体检」会把旧锚点和旧档位表变成验不过，这是真实副作用而非理论担忧。
> `serve` 默认只许绑 `127.0.0.1/localhost/::1`，绑其它地址必须显式 `--allow-public`
> （非回环一绑，市场、账号与审计面就进了局域网）；**「停」刻意不进 CLI**：一个能被远程带令牌调用
> 「停」的入口就是多开一处拒绝服务面，正确做法是容器 `stop` / `systemctl stop` / Ctrl-C。
> 备份包契约 `tt-server-backup.v1`：库用 **SQLite 在线备份 API** 取一致快照（**不是文件拷贝**——
> 本库跑 WAL，边写边拷会得到撕裂的库），清单记逐文件 sha256 与字节数、九张底账表的行数、
> 链长与链头、锚点概况；`verify` 逐条复核并**如实标注锚点签名没在包里核过**
> （`signatureChecked: False`，包里没有私钥，不该假称验过）；`restore` 有三道确认
> （无 `--yes` 是用法错误、目标已存在还要 `--allow-overwrite`、恢复前先跑一遍 `verify`），
> 覆盖前把旧库留成 `.pre-restore-<时间戳>`，恢复后逐表比对行数**并比对链头**——
> 行数对得上而链头对不上就是「被换过一整个库」，只看行数抓不到。
> 私钥默认**不进包**，`--include-keys` 显式带上并在输出里标「机密」。
> 自测 `tests/test_cli.py`（20 节 **261** 项）**全绿 / 0 红**，真子进程、真端口、真数据根，
> 含一次篡改最新审计行让 `doctor` 当场判红并点名行号、一次「删包里的字节就不放行」、
> 一次把包恢复到**另一个数据根并带走密钥**的换机演练（新机用恢复来的公钥仍验过全部锚点）。
> 写绿之前抓出并改掉六处真缺陷：`--port 0` 被 `or` 悄悄当成 8000（运维以为起了，其实监听在别的端口）、
> 五个命令组的 handler 只挂在 `health/whoami` 上导致管理面全部回「未实现的命令」、
> `tiers list/verify/effective` 取不到作用域位置参数而抛裸 `AttributeError`（补 `CLI_INTERNAL` 兜底 +
> 全流程「任何输出不得含 Traceback」断言）、`users set-quota` 一个旗子都不传时把
> `concurrentTasks` 当 0 发出去（服务端下限是 1，运维只收到一句 `INVALID_QUOTA` 看不出是自己没填）、
> `doctor` 会写（见上）、`_backup_restore` 读不到 `manifest` 键。

## 4. 未验收与边界（不许被读成已做）

- **真机无头环境未跑**：全部证据来自本机 Windows 子进程。台账「无头环境可用」这句里，
  **Linux / 容器内**的 `python -m app.cli serve` 与 `doctor` **未验收**。
- **优雅停机的信封输出无法在本机验证**：Windows 上 `terminate()` 是硬杀，
  所以「`serve` 收到 SIGTERM 后仍把 `{"stopped": true, "runtimeSeconds": …}` 信封打出来」这条
  **只实现、未验证**；自测只断言了「进程收得回来 + 端口不再应答」。
- **跨机恢复未验收**：换机演练是**同机不同数据根**（包恢复到新目录、带走密钥、新机验锚点全绿）。
  真实跨主机（不同文件系统、权限模型、SQLite 编译选项）没有实证，**不要写成「已可跨机迁移」**。
- **多进程并发安全未验证**：本服务端每请求开关连接（`app/db.py:517` 的 `tx()`），
  实测在**服务运行中**完成 `os.replace` 覆盖库且下一个请求立刻看到新内容；
  但 Linux 上「覆盖打开中的文件不报错、已持有的句柄继续读旧 inode」这一风险只在
  `manifest.restoreNotes` 里写成了操作要求（先停服务再恢复），**没有做成可验证的保护**。
- **密钥轮换超过 `MAX_KEYS=2` 的旧锚点验不过**这条仍在（与 #152 / #153 同一条边界，本刀没有解决）。
- **`users set-quota` 只写个人配额**：组织级配额走的是**后一刀**新建的 `orgs` 命令组
  （#158 / D-23，同为本窗口领地）。本刀落地时 `orgs` 还不存在，`--help` 里那句
  「组织级配额见 `orgs`」当时是坑位；现在该组已有 `list / create / quota get / quota set /
  budget / members` 六个动作，`tests/test_org_quota.py` 里逐条验过命令回显与退出码。
  合并台账时**不要再按「`orgs` 不存在」写**，也不要在本分片里重复计入 #158 的验收。
- **CLI 不覆盖**：技能、通道、定时任务、更新检查、市场内容管理、Agent 生命周期、对话与会话。
- **`tongtian-gateway` 的 pytest 族本轮未跑**：`tongtian-gateway/.venv` 里**没有 pytest 模块**
  （`No module named pytest`），这台机器上跑不起来；本刀**一行未改** `tongtian-gateway/**`，
  所以不构成回归缺口，但这是一个**环境事实**，请 W4 记进交棒清单。
