不是「两条链路已经统一」。

**进展（2026-11-03，W2 #143）**：

- **池里放的是引用**。`pool.json` 每行只带 id / 标题 / 描述 / 版本 / 来源路径 / 启停映射，
  正文永远现读原文件；自测直接断言清单文本里**不含**正文句子。这一条是「改一次两边生效」的
  结构前提，不是靠同步刷缓存做到的。
- **两个只读适配器**：`discover_installed()` 读 Rust 的 `{home}/skills/*/SKILL.md`（无 `SKILL.md`
  的目录不算技能；目录名不合法、正文超 512KB 都**点名说明**而不是静默少一个）；
  `discover_yaml()` 读平台层 YAML，并把 YAML 独有的**工具白名单 / 上下文模式 / 窗口配置**
  原样带进统一条目——「统一」不把弱的一边拉平。同名撞车时**已安装的本地那份优先**。
- **按专家启停**：`set_enabled(id, expert, bool)`；expert 为空串写的是**缺省位**，
  没单独设置过的专家跟随缺省。停用/启用**立即**反映到 `resolve_for_expert()` 的输出，
  不需要重启，也不存在「A 停了 B 也停」的串味。
- **输出形状就是执行面形状**：`resolve_for_expert()` 产出的每行正好是
  `runtime_context.normalize_skills` 认得的**九个键**（id/name/description/content/kind/source/
  suite/error/scanBlocked），自测把它原样喂进 `normalize_skills` 与 `compose_skills` 验证过——
  `#164` 交棒后接线只剩一次调用，不用再改形状。
- **依赖检查给中文原因且不静默跳过**：缺工具 ⇒「缺少工具：xxx」、缺连接器 ⇒
  「缺少 MCP 连接器：xxx」、缺前置技能 ⇒「缺少已启用的前置技能：xxx」，统一前缀
  「未进入本轮执行面」；调用方**没给**可用清单时说「未检查（调用方没有给出可用工具清单）」，
  并且**照样放行**——不谎称通过，也不拿没检查当理由拦人。
- **草案六道闸**：`add_draft()` 落 `{home}/skill_pool/drafts/{id}/SKILL.md` + 池内 `status: draft`
  + `default_enabled=False`；`resolve_for_expert()` 显式跳过草案并说明；被强行启用后仍不进执行面；
  空正文/超长/已存在的草案**拒绝写入且不覆盖**。`promote_draft()` 人工确认后**复制**进
  `{home}/skills/`（原件留池里做审计痕迹），目标已存在时**拒绝覆盖**，确认人写进回执。
- **清单读坏了就不写**：`pool.json` 损坏 / 根节点不是对象 / 缺 `skills` 数组 ⇒ 带 `load_error`
  返回、`save()` 拒绝覆盖（保住最后一份真相）、`set_enabled()` 与 `drop()` **当场被拒并给出
  「读坏了」这个原因**（不是拖到保存那一刻才失败），只读视图 `pool_view()` 里 `writable: false`。
  单条条目缺字段按缺省解析，整池不作废；**认不出的 `status` 归成草案而不是当成就绪放行**（失败关闭）。
- **源文件消失不删条目**：外接盘拔掉、临时目录挂载点失效时条目保留并说明「正文文件当前不在盘上」，
  文件回来下一次同步自动恢复——静默删除会把用户的启停状态一起抹掉。
- **跨语言对齐四件**（用例直接读 `src-tauri/src/skill/mod.rs` 源码做钉）：`MAX_SKILL_MD_BYTES`
  同为 `512 * 1024`；技能目录同为 `base.join("skills")`；标识长度同为 64（**用例是 64 字符通过、
  65 字符被拒**的语义断言，不是比字符串）；frontmatter 解析 **9 条对照表**逐条一致
  （含 `>` / `|` 折叠块取缩进续行、只认 name/description 两键、值去引号、无 frontmatter 时用
  正文首个非标题段落兜底、frontmatter 前有空行时那句被当成描述）。

**本刀在跑绿之前抓出的五处真缺陷**（都改在产品代码里，不是只调期望值）：

1. **`tools.allow` 被当成依赖**：平台层 YAML 的白名单（限制能用哪些工具）被映射进
   `requires.tools`（缺了就跑不了），后果是本机少装一个工具就把技能挡在执行面外。改为
   `requires` 只收 `mcp.servers`（连接器没接入时技能确实执行不了，按依赖处理是诚实的）。
2. **同 id 换来源永不生效**：用户把与内置 YAML 同名的技能装进本地目录后，重同步只更新版本，
   引用还指着老 YAML ⇒ 装的这份读不到。改为来源跟随「已安装优先」并说明，**启停状态保留**
   （启停属于专家，不属于文件）。
3. **坏清单上的写操作只做内存改动**：`set_enabled()` / `drop()` 当场返回成功，错误要等到
   `save()` 才暴露——给用户「已经改了」的错觉。改为写操作直接拒，并把「读坏了」作为原因交出。
4. **空白正文技能被摘出执行面**：与 Rust「把整份 `SKILL.md` 原文交给模型」的行为不一致
   （统一注册表最不该出现的就是这种分叉）。改为**原文照常进清单**，同时在 `error` 里写明
   「正文是空的，模型读到的是空提示」，两条链路保持同一份事实。
5. **跨语言钉写成比字符串**：标识长度那条用 `pattern.endswith("{1,64}")` 断言，pattern 以 `$`
   结尾就永远红，且就算绿也没证明什么。改为 64 字符通过 / 65 字符被拒的语义断言。

另有三处**会白过的用例**在跑之前拆掉：`… or True, ""` 式空断言、`if False else None` 的死清理行、
以及「两个专家都拿到同一个技能」原本断言的是**清单长度等于 1**（把「共享引用」验成了「池里只有
一个技能」）——改为比较两个专家拿到的**那一行是否完全相同**。
