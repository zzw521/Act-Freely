## 2. #144 落地了什么（工程事实，给要接手的窗口）

**① 注册判定只有一个地方。** `engine/tool_grants.py::registration_plan()`（行 776 起）返回
`{"run_command": {"registered", "reason"}, "run_shell": {…}, "fetch_url": {…}, "container": container_state()}`。
`install()`（行 826）现在**只读结论**，体内不再自行派生 exec / shell / network 三个开关——
这条由 `tests/unit/security/sandbox-grants-contract.test.ts` 用**反向断言**钉住
（`installBody` 不得再出现 `self.exec_allowlist` / `self.shell_enabled` / `self.network_allowlist`）。
三条条件一条没少（命令执行 = 授权 ∧ 白名单非空；通用 shell = 命令执行授权 ∧ shell 授权；联网 = 授权 ∧ 白名单非空），
新增第四条：**`container["enabled"] and not container["ready"]` ⇒ 执行面不注册**。
理由写进了 docstring：技能正文、套件指令、扩展声明的可执行件全靠 `run_command` / `run_shell` 落地，
容器起不来时把它们注册上去 = 让扩展内容以宿主权限跑。**「未授权即不注册」而不是注册后拒绝**，
这样模型的工具面上根本没有那一项，不会被诱导去试。
联网那一项不受容器条影响（进程内 `urllib`，不产生子进程）——判定里显式 `net = item(True, "")`，
测试钉的就是这行字面。

**② 「这个扩展声明了什么能力」有一份可核对的清单。** 新增 `engine/extension_decls.py`：
`observe(runtime, task_id)` 在 `engine/server.py:1874` 被调（**每轮任务开始摊一次桌面推来的 runtime**），
`snapshot()` 原样交给车道端点 `GET /api/exec/extensions`（`engine/routes_exec.py`）。
三条口径别读歪：**(a) 不接受调用方给目录、不去盘上扫扩展包**——扫盘会把「装了但本轮没进执行面」
的东西说成可用；**(b) 没跑过任务时如实返回 `observed=false` 加两条说明**，不伪造一份空清单；
**(c) 上限是可见的**（`MAX_ENTRIES=200` / `MAX_NAME_CHARS=80` / `MAX_UNGRANTED_COMMANDS=20`，
超了在 `limits` 里点名）。键名 camelCase（`runCommand` / `runShell` / `fetchUrl` / `container`），
界面直接可读。执行面那三项的 `registered` 与 `reason` **与 `registration_plan()` 同源**，
所以「界面显示可用而模型点不通」这种分叉在结构上不可能出现。

**③ 通用 shell 通道也能进容器了。** 这是本刀唯一动 Rust 的地方：启动器加
`--raw-command-line`（`src-tauri/src/sandbox/cli.rs` 行 124 解析、`win.rs::resolve_program(program, args, raw)`
行 429 起，`raw` 为真时 `tail = args.to_vec()` **不再逐个 `quote_arg`**）。
缺省关闭，**终端 / MCP / ACP / Hooks 四条既有路径的字节形状一字不变**（`cli.rs` 的
`raw_command_line_defaults_off` / `parses_raw_command_line_switch` /
`raw_command_line_keeps_the_tail_verbatim`，`win.rs` 的
`raw_command_line_keeps_the_shell_tail_verbatim` / `without_raw_command_line_quoting_is_unchanged` /
`raw_command_line_still_rejects_a_missing_program` 钉着；`quoting_matches_msvcrt_rules` 是没改的那一半）。为什么要它：D-48.4c 那条坑——
`cmd.exe` 不是 MSVCRT 的 argv 消费者，Python 侧给列表时 `"` 被转义成 `\"`，`cmd.exe` 不吃，
带引号的命令此前 **rc=0 静默空跑**。`sandbox_launcher.wrap(..., raw_command_line=True)` 交出
`list2cmdline([shell,'/d','/s','/c']) + f'"{raw}"'` 那种整串，容器令牌 / 环境过滤 / 网络能力 /
Job Object 一档不少——**改的是引号，不是边界**。

**④ 容器 ACL 的真实语义（谁想在容器里放文件都得先知道）**：`win.rs::apply_acls()` 对
`--workspace` 与临时目录给 `(OI)(CI)M`，对 `--read-dir` / 运行时目录给 `(OI)(CI)(RX)`，
并对 `sensitive_paths()`（含 `work_home()` = `TONGTIANWORK_HOME`）**整棵 `(OI)(CI)(F)` 拒绝**。
**拒绝压过授权**：把 `--workspace` 指到数据根里，容器子进程照样写不进去
（`PermissionError [Errno 13]`）。所以取证脚本的工作目录必须在数据根之外，
这条现在也是探针里的正向断言，不是踩坑笔记。

**⑤ 资源上限只做到一半**：Job Object 只设了 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`（win.rs:645），
**没有 CPU / 内存配额** ⇒ 台账验收那条「超资源被终止」只算部分成立，我没把它写成已验。

`C:\Users\admin\AppData\Local\Temp\w4-d08-probe3.txt`（**29 项 `^[PASS]` / 0 红**）。
五道控制缺一不可，写进 docstring 了：

1. **宿主对照**——临时摘掉 `TT_SANDBOX_BIN` 跑同一条带引号的命令，连得上本机回环 ⇒
   证明命令真的跑了，而不是容器内空跑；
2. **会跑对照**——容器内不碰网络的命令照常成功、真的写进工作目录 ⇒ 拒绝来自出线不是容器坏了；

1. **界面面板**消费 `GET /api/exec/extensions`（「这个扩展声明了什么能力」清单 + 安装时展示将获得的权限）。
