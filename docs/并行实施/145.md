## 8. 本刀抓出并修掉的引擎缺陷（都是「绿着但不对」的那类）

1. **草案明明写成功了，回话却说失败**：`add_draft()` 的第二个返回值是**成功提示**
   （「草案技能「…」已写入 …，状态为未确认；…需人工确认后启用」），
   只有第一个元素为 `None` 时它才是错误。本刀按「第二个非空就是失败」写 ⇒
   每次 `browser_record(save)` 都印「错误：草案未写入。草案技能「…」已写入……」，
   落盘的文件真实存在、审计里还是 `ok`——一条自相矛盾的回话。
   修法：判据改成 `if entry is None:`，成功时**原样转述** `add_draft` 的那句（引擎不再编一份
   「已启用」），草案路径取 `entry.source.path`。
2. **回放的步骤归一化把 `input` 与 `sensitive` 丢了**：`normalize_replay_steps` 只留
   `action/label/url/direction/amount` ⇒ 草案里那两个键走到回放已经无从判断，
   「这一步需要输入位」与「这一步是密码框」两条判据同时失效（后者会退化成照抄 `value` 打字）。
   修法：两个键一起带上，且敏感判定**按当前标签重新算**（`_looks_secret`），
   不指望模型抄写清单时把 `sensitive` 也抄对。
3. **占位符抄进 `value` 就当正文打**：`_step_value` 原本只看 `input` 位。真实清单里模型经常写
   `{"action":"type","label":"搜索","value":"{{搜索-3}}"}` ⇒ 会把字面量 `{{搜索-3}}` 打进页面，
   还回一句「完成」。修法：`value` 也是 `{{…}}` 形状时同样按占位符处理（两处任一命中即查 `inputs`）。
4. **草案不是「改一个输入可回放」，只是一份人读的流水账**：`_draft_body` 漏了 `submit`
   （「输入后按 Enter」这种一步半的动作在草案里消失了）与滚动屏数，且没有可执行清单。
   修法：补两段的文案，正文末尾附一段 ```json``` 的**可回放步骤数组**（剥掉 `n`/`hasValue`
   这类录制侧记账字段），回放直接吃这一段——「草案 → 改输入 → 回放」才真的是一条闭环。
5. **`browser_press` 的密码框守卫只挡了不常用的那条路径**：写的时候只在 `index` 非零（先按序号聚焦）
   这支查了 `isPassword`，而**默认是 `index=0`**——「直接发给页面当前聚焦的元素」这条最常被模型选的路径
   什么都没看就把键发出去了，而 `KEY_CODES` 白名单里有 `backspace` / `delete` / `space`，
   等于可能一次清空别人正聚焦的密码框；文档与 `边界` 里那句「密码框拒绝」当时是**过度声明**。
   修法：不带序号时先发 `ACTIVE_JS` 读 `document.activeElement`，是密码框就整条拒绝（**在 `/approve`
   之前**，不烧一次系统确认框、一个键也不派发），普通元素则在回话与确认框文案里说清「发给页面当前聚焦的
   input「搜索」」，读不到聚焦对象时不编造。**这条是本刀收尾自查出来的，不是自测逼出来的**——
   断言写在生产代码之后，所以为了证明它们不是空断言，做了一次**反向对照**：把那行判据临时改成
   `if probe.get("isPassword") and False:` 复跑自测 ⇒ **210 项 / 3 项转红**
   （「被拒」那条直接印出「已按下 Backspace（发给页面当前聚焦的 input「密码」）」，
   派发计数 2→4，`/approve` 里多出两条 `press`），改回后 213 / 0 红复跑通过。
6. **模块 docstring 写了不存在的符号名**（`browser_record_save` / `_record_value` / `_feature_action`）：
   这类句子在改造中会变成下一个人踩的坑，已改成实际存在的符号（`browser_record` / `_record` /
   `_looks_secret` + `_step_value` / 四个 `_x_tool` / `has_feature` / `gated_actions`），
   并把「还没做的两件 + 缺的是桌面壳哪一半」写在同一份 docstring 里。

另有三处**测试自己不对**（不是产品缺陷，但会让绿读成假绿，一并记在这里）：
「分级不新增预算数字」的断言原用 `isinstance(v, int)`——Python 里 `isinstance(True, int)` 为真，
布尔开关全被当成数字混进判据（改 `type(v) is int`）；`sorted(p.rglob(...) for p in [...]) == []`
永远是假（比较的是生成器列表，改成 `list(Path(...).rglob("SKILL.md"))` 直接断言）；
`fake_gate` 的调用清单没被 `Harness` adopt ⇒ 断言「每一步仍过网关」时 `h.calls` 恒空
（现 `post.calls` 由 `fake_gate` 挂出、Harness 接管）。
