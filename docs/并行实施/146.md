## 4. 仍未做（不许被读成已做）

**引擎侧缺口**

1. **发附件六通道全未接入**（`supports_media_out = False`）：钉钉要先上传换 `mediaId` 再拼它自己的附件
   载荷，那个载荷本机没验过，`media_out_note` 因此写「请在通天办公的工作区里查看」，不假装能发。
2. **typing 无一条通道声明 `supports_typing=True`**：框架只在 True 时下发（`im_channels.py:823`），
   所以「支持 typing 的平台显示输入状态」今天是**未接入**，不是未验收。
3. **只有钉钉能收附件**：Slack / 企业微信 / 飞书 / 个人微信 / 元宝的 `parse_event` 只交文本部分，
   各家 `media_in_note` 如实写明「尚未接入附件下载」。企业微信官方有媒体下载接口，本刀没接。
4. **`dedupeSeconds` 只挡同人同文**：语义是「重复抑制」，不是「合并成一条回复」；
   连发五条不同内容仍会起五个任务（策略默认 `mention` 时群里只有被 @ 的那几条会起）。
5. **群上下文暂存在内存**：`groupContext=memory` 只在本进程存活期间攒，重启即空，
   不跨通道实例共享，`shape.contextLimits.note` 里明说；要长期记忆得走 D-35 那类设计。
6. **`ChannelGateway`（platform 网关）没接桌面主链路**，本刀一行没碰，台账 §1233 那句仍然成立。

## 8. 本刀抓出并修掉的引擎缺陷（都是「绿着但不对」的那类）

1. **限流额度是界面装饰**：策略里的 `maxMessagesPerMinute` / `burst` 存在表里，但发送前没人把它落到闸门
   ⇒ 用户设了每分钟 60 条、引擎仍按 10 条挡。修法：每条入站在 ⑤ 之前 `governor.apply_limits(...)`，
   额度**变了才清桶**，且**绝不动平台冷却**（`apply_limits` 不碰 `cooldowns`）。
2. **超时不记账**：`bounded_send` 超时后只回一句 note，计数里没有 `timeouts` ⇒ 流量面看不出
   「今天有 N 条卡在发送」。修法：带 `governor` 时 `mark_timeout()` 记一笔，调用方拿到的仍是中文 note。
3. **通道自报「附件没发出去」被吞**：`send_parts` 返回的媒体未送达说明曾被当成发送成功，
   台账里就是一条看起来已送达的回复。修法：`return str(returned or "")` 原样交回，框架在台账另起一条
   「（引擎状态：…）」，不进 `out` 正文。
4. **`/api/im/traffic` 读了一个不存在的键**：`view()` 里没有 `cooledKeys`，`rateLimit.get("cooledKeys")`
   恒为 `None` ⇒ 冷却中的会话永远报 0，中文 note 变成谎话。修法：读 `blockedConversations`，
   自测里造一个真在冷却的实例并断言 note 说「1 个会话在平台冷却中」。
5. **同标识跨类型互相继承策略**（约束 D 的实质违反）：策略实例一级曾用裸 `channel_id` 做键，
   两个**不同类型**、标识恰好同名（都填 `ding-1`）的实例会读到同一份群激活策略，
   等于把 A 通道的 `always` 漏给 B 通道。修法：`instance_scope()` 与 `instance_key` 同形
   （`类型:实例标识`），`channel_id` 为空或等于类型名时回裸值（D-41 之前只有一个实例，老配置不许失效），
   并加「跨类型不继承」「裸键仍可作为会话作用域」两条断言。
6. **附件目录名没有长度上界**：会话标识 / 实例键直接当目录名，长标识（或消毒后仍长的）撞文件系统
   单段 255 上限，且不同长标识可能截在同一处。修法：`MAX_NAME_CHARS = 80`，消毒或截断时补
   `sha1[:10]` 指纹——同实例每次算出同一个，不同标识不撞一起；顺带把 Windows 非法字符
   `< > : " | ? * / \` 全部换成 `_`（钉钉实例键里的 `:` 曾让两个实例的附件并进同一个目录）。
