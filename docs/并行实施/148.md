## 2. 口径句（供「更新N」条目使用，编号由 W4 合并时定）

> **① 落地范围（D-34，W6 #148 引擎半边）**：新增编排层
> `engine/team_runtime.py`（`TeamRuntime` + 三份单文件 JSON 存储
> `team_registry.json` / `team_rooms.json` / `team_jobs.json`，都落在
> `data_paths.engine_home()` 根下、与 D-48 三份工单账本同处）、车道
> `engine/routes_orchestrate.py`（**18** 个端点，前缀 `/api/experts` +
> `/api/checkpoint`，`server.py` 已挂）、工具车道 `engine/toolkit_orchestrate.py`
> （`team_dispatch` / `team_room_status`，**今日一件都不注册**，开关见 §5）。
> **② 最重要的一条映射（约束 A 的落法）**：房间里两类执行体住在**同一张工单表**里——
> 主持人 = `ticket_id = 房间`（房间 id 就是主持人会话 id），成员 = `ticket_id = 房间~成员 id`。
> 于是 D-48 已验收的三件事直接继承、**没有第二套保序**：投递即落盘（同一个
> `TicketInbox`，本层不自开队列）、同工单保序（同人第二次派工走 `existing-worker`
> ⇒ **同一成员串行**）、槽位与人用预留（不同成员各占一单 ⇒ **不同成员并行**且挤不掉人）。
> 唤醒投递只走 `TicketWorkerRegistry.start_or_wake`，本层没有第二个 `append`。
> **③ 回叫不占主持人槽位（设计口径，读端点前先看）**：`notify_host` 先问
> 「主持人这张单有没有活绑定」——有就当轮唤醒（`origin="agent"`，走 `existing-worker`）；
> 没有就**只落耐久收件箱**（`delivered: "journal-only"`，领取号带 `pending-` 前缀，
> 它不是一份真领取），等主持人下一轮或重启补查收走；**不去领 Agent 槽位**——
> 团队层替主持人领槽位会挤掉成员、且那份绑定没人会去 `end`，槽位永久泄漏。
> 既没有活绑定也没有耐久箱时如实回 `ok: false`，不谎报「主持人已收到」。
> **④ 状态码口径**：编排层业务码 `MEMBER_INFLIGHT` / `LEDGER_PENDING` 回 **409**
> （冲突，调用方重试前要先收口），其余不合法入参回 **422**，缺注册表/缺参数回 **400**
> （`routes_orchestrate.CONFLICT_CODES` 是这份表唯一来源）。
> **⑤ 编制校验不猜**：建队/换人要对着**专家注册表**逐条校验，注册表只有两个来源——
> 请求里的 `experts`（桌面建队时还没有会话）或按 `session` 从 `server.py._TASK_SESSIONS`
> 读 `runtime.experts`；两条都拿不到就 **400 并说清「没有第二份可查」**，
> 绝不按名字猜一个专家（猜出来的编制会在派工时把活投给一个不存在的人）。
> 移出成员这条**不要求注册表**：台账里存了主持人/成员的姓名快照，够判「在途」。
> **⑥ 有意不做**：成员不用自己的工作区目录（仍共享任务工作区，D-34 方案第 2 项的后半
> 留给桌面/引擎装配）；IM 通道转播（方案第 6 项）没动；`kind=team` 的专家仍只是注册表
> 条目，团队编制存在本层而不是 `expert_runtime`（那是 W6 领地但改它会把专家语义劈成两半）。

**进展（2026-11-04，W6 #148）**：

- **三份存储同构但不越界**：`_DurableStore` 是 `TicketInbox` 那三条纪律（tmp+`os.replace`
  原子写、坏文件改名 `.corrupt-*` 让路并暴露 `loadError`、到上限**拒收**而不是静默挤掉旧记录）
  的第二次实现，**仅限编制/时间线投影/派工台账这三份新事实**；唤醒投递仍只有收件箱那一份。
- **重启降级写在加载里**：`JobStore.on_load` 把 `queued/running` 一律降成 `interrupted`，
  并顺带把 `checkpointState == "inflight"` 的索引一起降（记 `checkpointInterruptedAtMs` +
  `checkpointInterruptedByRestart`），随后落一次盘——不落盘的话每次开机都要重新「降级」一遍，
  `interruptedAtMs` 会被刷成开机时间，中断时间就成了假的。
- **在途判定跨全部房间**：`TeamStore.rooms_of_team()` + `TeamRuntime._team_inflight()`。
  `room_of_team` 只回第一个房间，**只许当展示用**；一份编制绑过多轮会话时，只看第一个房间
  会允许把一个正在别人房间里跑的成员移出去。
- **重复收口不再二次上墙**：`member_reported` 先问台账 `transition`，被拒（`ended` 二次收口
  或查无此单）就**直接返回**并回 `"callback": {"ok": false, "reason": "台账没收下这次收口，没有发起回叫"}`——
  否则同一份结论主持人会读两遍（一次上墙、一次回叫）。
- **槽位满时派工如实失败**：`dispatch` 拿到 `start_or_wake` 的拒绝就把这条派工记成
  `refused`（不落 `checkpointKey`）并把原话带进回执，不自开队列兜底。
  自测 §2 用「四个成员占满三个 Agent 槽 ⇒ 第四个如实失败」钉住。
- **主持人待读从磁盘答**：`host_pending` 直接读耐久收件箱按房间查，不依赖内存箱还在不在；
  引擎重启、内存箱蒸发之后照样答得出「谁在等主持人」。
