## 3. 状态明细（D-32 一节下新增）

**状态**：**进行中（2026-11-04，W3 #151 落地令牌层与组件库半边）**——令牌登记表 +
层叠解析器 + 六个 React 件 + 七段 CSS 片段 + 产物样式段（搬运声明、两道发版闸）都有自测钉住，
快照面板已实际消费；**产物生成侧未接线、真实渲染与换肤交互未验收**。

**进展（2026-11-04，W3 #151）**：

- **颜色只有一个来源这件事被钉成三件事**：① 登记表不含值（扫源码不许有十六进制）；
  ② 产物嵌的是 `globals.css` 原文声明块，不是解析后的读数（抄值那一刻就有了第二套肤）；
  ③ 组件库与片段的每个令牌引用都要同时在登记表与 CSS 声明里存在，缺一即红。
  顺带把 `globals.css` 里那条「皮肤亮块与暗色基座同特异性、靠书写顺序定输赢」的坑
  写进了 `resolveTokens`——解析器只复现「条件全中才算匹配、后写的赢」，**不自己发明优先级**。
- **chip 的底色与文字色成对给**：`KIT_CHIP_TONES` 七档每档都是 `{bg: 'chip-*', fg: 语义色}`
  一条记录，测试同时反向钉住「bg 必属 chip 组、fg 不得也是 chip-*」，并把这条口径**算成真数**：
  七档底×字在八套组合下最低的一档是 teal 亮档 4.95:1（全部 ≥4.5），而同一张浅底压近白字
  （`--tt-chip-*` 配 `--tt-cta-ink` / `--tt-surface`）只有 1.10–1.16:1——两边分开挑就是这种糊。
  快照面板的「档→色」映射表因此**只允许写色调名**（`public: 'success'` 这类），
  映射表里出现 `--tt-` 就是第二个落点（反向钉）。
- **模式不变性从「猜名单」换成「现算 + 按皮肤豁免」**：`tokensStuckBetweenModes(css, uiStyle)`
  给事实，`MODE_INVARIANT_EXEMPTIONS` 给「设计上允许不翻」的登记（default / glass / parchment
  空，classic 只豁免 `shadow-card`——那份皮肤故意把投影关掉），`unexpectedModeInvariants`
  给可疑集合。产物发出去前可疑集合必须为空，否则报「有 N 个令牌亮暗同值（暗色档漏了）」。
  残缺样式表的回归用例真造了一份（正则**行首锚定**地删掉 `html[data-theme='dark']` 整块——
  不限定就会切到注释里那句同名字符串，删多），并钉住健全的那份**不许**抛。
- **组件库不是空头导出面**：导出面恰好八个由测试锁死；面板把六个件全用上了
  （`<KitCard>` 六处、`<KitChip>` 分级、`<KitEmptyNote>` 空态、`<KitFieldRow>` 状态行、
  `<KitRow>` 未验收条目、`<KitSectionTitle>` 区块标题），所以「新增件没人用」这种死码
  在本卡不成立。**展示层零行为**：组件里不许出现 `onClick` / `useState` / `useEffect` /
  `fetch(` / `engineFetch` / `tongtianAPI` / `.invoke(` / `styled(` / `createTheme`
  （`from '@mui/material'` 只取 Box / Typography，不引第二套样式运行时）。
- **与既有强制件不打架**：`a11y-surface-contract`（28 项，走全部 `src/renderer/**.ts(x)`、
  跳过 `theme/`、十类棘轮基线为空）与 `theme-contrast-contract`（76 项，八套组合实算）
  在新建组件后**零新增违规**；本刀没动它们的基线。

**未验收与边界**：见 §4，全部按「产物没真跑过就写未接线 / 未验收」的口径落文字，不写「已支持」。
