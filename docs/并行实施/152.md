## 2. 口径句（供「更新N」条目使用，编号由 W4 合并时定）

> **① 落地（D-44 服务端半边，本批次 W1 #152）**：新增 `tongtian-server/app/model_tiers.py`
> ——档位表（`auto` / 高级 / 基础 / 经济 → 模型链）按 **全局 / 组织** 两级作用域下发，
> 个人账号复用既有 `personal-<uid>` 组织声明，所以「按账号下发」与「按组织下发」是同一条路，
> 没有第二套表。`revision` 由服务端单调递增：**内容不变的重复发布不升版**（幂等），变了才 +1；
> 「回到上一版好策略」实现为 `POST …/revert`——把历史那一版的**内容**重新发布成**新版本号**，
> 而不是把版本号调回去，因此客户端「只接受递增版本」这条判定永远成立，回滚同时入审计。
> 每版带 `digest = sha256(规范化文档字节)` 与 **RS256 签名**（受众独立：
> `aud=tongtian-tiers`、`typ=model-tiers`，公钥走既有 `/.well-known/jwks.json`，
> 档位签名不能当访问令牌用，已实测 401）；签名保护的是**摘要**，正文随响应传输，
> 所以客户端验签后必须再复算一次 `digest`。客户端拉取 `GET /api/v1/model-tiers/effective`
> 带 ETag/304；服务端没有表时**如实 404 并在中文说明里点名「应继续使用本地 models.json」**，
> 不给空表冒充满配置。`GET /api/v1/model-tiers/at?revision=N` 让任务详情能按元数据里的版本号
> 回看当时那一版策略——这是「选档可解释」在服务端唯一能兑现的抓手。

## 3. 状态明细（D-44 一节下新增）

**状态**：**服务端半边已落地（2026-11-03，W1 #152）**——下发、版本单调、签名、两级作用域、

**进展（2026-11-03，W1 #152）**：

- **两张新表，走服务端既有增量迁移惯例**：`app/db.py` 的 SCHEMA 末尾追加
  `model_tier_tables`（每个作用域一行当前版）与 `model_tier_revisions`（只追加的历史）。
  **索引声明位置的坑已避开**：这两张是**整表新建**，索引引用的列一定同时存在，所以索引
  可以写在 SCHEMA 里；`usage_rollup.idx_usage_rollup_org_dept` 那类「给旧表补列」的索引才必须
  挪到 `init_db` 补列之后——注释里把这条区别写进了 SCHEMA，防止下一个人照抄错。
  旧卷升级顺序：`CREATE TABLE IF NOT EXISTS` 建表 → 无需补列 → 无需回填 → 完。没有 `ALTER`、
  没有 `DROP`、不动任何既有表。
- **文档校验在服务端做严**（`TierDocumentIn`，`extra="forbid"`）：未知档位名 / 空模型链 /
  链内重复 / 链引用未登记的模型 id / 缺省档是 `auto` 却既无 `autoPolicy` 也无 `auto` 链 /
  `autoPolicy` 的规则或回落指向未声明的档位 / 契约版本不受支持 / 多余字段（含 `masterKey`
  这类想塞密钥的写法）——七类各有用例拒绝，错误码统一 `TIER_INVALID` 带中文定位。
  模型链只下发 **id 与元数据**（provider / upstreamModel / contextWindow / maxOutputTokens），
  **没有任何密钥字段可填**，与 D-44 方案第 4 条「协议不变、客户端仍直连模型端点」一致。
- **作用域优先级**：组织表 → 全局表 → 无。`DELETE` 撤销某作用域的表后立刻回落上一层，
  历史版本保留可回看；「撤销下发」这件事本身入审计（`model_tier.withdraw`）。
- **验签巡检**：`GET /api/v1/admin/model-tiers/verify` 逐张重算摘要并验签，任何一张对不上
  就点名 `scopeKind/scopeId/revision` 并给中文原因。实测：DB 里改一个字节
  （把 `advanced` 的链换成小模型）⇒ `untrusted=1` 且原因含「摘要」，同时该账号的
  `/effective` 响应里 `digest` 与文档不再自洽 ⇒ 客户端据此拒绝，**篡改不会被读成配置**。
- **审计入链**：`model_tier.publish` / `model_tier.revert` / `model_tier.withdraw` 三个动作
  写进既有 `admin_audit` 哈希链（记的是版本号与 64 位摘要，不记正文），档位写入之后
  `/api/v1/admin/audit/verify` 仍可验（既有 M4 链未退）。
- **角色边界**：拉取要登录（未登录 401），管理面只认平台管理员（普通用户 403）。
  路径注册顺序沿用既有约束：**必须先于市场通配路由**——`/api/v1/model-tiers/effective`
  是两段路径，否则会被 `/api/v1/{plural}/{item_id}` 抢走、把 `effective` 当成条目 ID
  （和 D-07.4 桌面索引那次同一个坑，`main.py` 注释里点名了）。

  轮换两次以上的旧档位表会验签失败——本刀没有实现「自动重签全部表」的运维动作，
  `POST …/revert` 到当前版本会被 `TIER_NOT_AHEAD` 拦住，所以只能重新 PUT 一次。这条留给
  下一刀或收口批次，**不要读成已支持无限次轮换后仍可验**。
- **D-14 的服务端配置载体共用**没有落地：本刀的表只服务档位，`per_task_limit_tokens` 那类
  预算配置仍走引擎/桌面侧，两处没有合并成一张载体表（台账 D-44 方案里「与 D-14 共用服务端
  配置载体」这句保持未兑现）。
