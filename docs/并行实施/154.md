## 2. 口径句（供「更新N」条目使用）

> **D-19 服务端三件齐（W1 #154 刀 A+B+C）**：生产口径下 `/docs` 与 `/openapi.json` 是关掉的
> （`TT_SERVER_ENV=production` 时 FastAPI 不暴露），所以第三方过去**没有任何一份对外的说明书**；
> 网关侧早有 `tongtian-gateway/CONTRACT.md`，控制面这边一直没有。本轮补的不是「一份手写的文档」，
> 而是**一份会被真路由表打脸的契约，加一个真能按它跑的客户端**。
>
> **刀 A**：`app/api_contract.py` 里 **28 条**稳定操作逐条声明方法、路径、鉴权档、请求参数、顶层响应键、
> 错误码、幂等标注，`find_problems()` 拿运行中的 `app` 做五件事——路径必须在实际路由表里存在、声明的鉴权档
> 必须与实际挂载的 `Depends(require_user/require_admin)` **同名**、声明的错误码必须在 `app/*.py` 源码里
> 找得到、引用的速率限制模板必须在调用点**逐字还在**、**清单说接了幂等键的 op 必须在
> `idempotency.SUPPORTED_SCOPES` 里真注册了**（这条是刀 B 落地后加的，专治「清单自说自话」）；
> 再加 `GET /api/v1/contract`（匿名可读、含 `problems`）与 `GET /api/v1/contract/verify`，
> 以及所有 `/api/v1/*` 响应自动带 `X-TT-Api-Contract: tt-server-api.v1` 头。**契约说谎比没有契约更糟**，
> 所以正向用例全部**真打 HTTP**，反向用例**故意把契约改坏 11 处**要求自检逐条报出来。
> 探针档里**删掉了「只声明不真打」这一档**（`PROBE_MODES` 里没有 `declared`）：想新增一条没得打的枚举值
> 会被自检直接判未知模式——要偷懒就得先改机器，改机器就会被看见。**28 条现在每条都被真打**
> （17 条通用 GET + 4 条市场流程 publishSkill / publishSuite / detail / download + 7 条在「准备数据」里
> 真打过的写操作），刀 A 欠的 `market.detail` / `market.download` 由市场流程真条目补上，
> 而且 `item` 的键集合按 skill / suite / mcp **三种类型分别**钉住（它们的顶层键确实不同，不是抄错）。
>
> **刀 B（`Idempotency-Key` 写侧强制）**：`app/idempotency.py`（278 行）+ `db.py` 一张新表
> `idempotency_keys`（整表新建、索引同批建在 SCHEMA 里，不给旧表补列 ⇒ 不触发 W1 专属约束 A 的旧卷升级时序；
> 旧卷升级后这张表是空的，行为逐字节等于升级前）。作用域是 **(操作, 调用者, 键)**，摘要 sha256 覆盖
> `{op, binding, body}`——**部分更新的显式字段集也算进摘要**（`orgs.quota.put` 只改 `enforce` 与只改
> `totalTokens` 不能算同一件事）。口径四条写在契约里而不是埋在代码里：① **不带键的请求逐字节走原路径**
> （接键不改变旧行为）；② **业务失败不占键**（预留当场释放，重试是真的重跑，别把幂等键当「上次也报错」的保证）；
> ③ **回执原文落 SQLite 明文字段**，所以**签发令牌的四条路径（register / login / refresh / logout）有意不接**
> ——不拿凭据换重放便利；④ 回执 >64KB **不缓存**，同键重试改为真的重跑（宁可重跑也不装作重放）。
> 键形状 `^[A-Za-z0-9._-]{8,200}$`；执行中租约 60 秒（进程被杀不会永久占键，到期能被接管）、回执 TTL 24 小时、
> 到期只**懒清**不起定时任务；重放响应带 `X-TT-Idempotent-Replay: true`。新错误码 4 个：
> `IDEMPOTENCY_KEY_INVALID`(400) / `IDEMPOTENCY_SCOPE_UNSUPPORTED`(400) / `IDEMPOTENCY_CONFLICT`(409) /
> `IDEMPOTENCY_IN_PROGRESS`(409，带 `Retry-After`)。接键的 5 条真路径：`market.publishSkill` /
> `market.publishSuite`（multipart，摘要在读干请求体之后算，包内容进摘要）/ `usage.report` /
> `orgs.create` / `orgs.quota.put`。最硬的一条自测是**累计值回归**：不带键重发 `usage.report` 会把用量
> **真的加两遍**（这是产品既有语义，本刀不改），带同一把键重发拿到原回执、库里只有一份——
> 幂等键在这里救的是数据正确性，不是方便。
>
> **刀 C（最小 SDK）**：`app/sdk/`（`client.py` 787 行 + `__init__.py`）**纯标准库**——不是口头承诺，
> 自测里用**子进程真 import** 反查源码没有第三方依赖；`Client` 上 **28 个方法**用 `@stable(op_id)`
> 注册，方法↔op 的映射、路径模板、`MARKET_PLURALS`、幂等支持集**全部与服务端清单机器比对**（漂一条就红）。
> 三条设计口径：① **只在可证明安全时自动重试**——GET、或带已登记幂等键的写、或请求**根本没送达**的
> 连接层失败，其余一律把错误交回调用方；② **退避时长只读服务端的 `Retry-After`**，没有就立刻抛，
> SDK **不自建退避表**（服务端改限流数字不必改 SDK）；③ 401 只**刷一次**令牌，不循环刷。
> 错误类型映射逐条与契约声明的 HTTP 状态比对，且**反向要求**：SDK 特殊映射的每个机器码都得在
> `ERROR_CODES` 里声明过——这条当场抓出**三个真在源码里抛、却从未登记进契约的码**（`ITEM_EXISTS` 409 /
> `ITEM_NOT_FOUND` 404 / `PACKAGE_ID_MISMATCH` **400**），已补进清单；同时把 `NOT_FOUND` /
> `PACKAGE_ID_MISMATCH` 从映射表**删掉**：400 不能映射成 `ConflictError`，宁缺不假。
> `check_tier_digest` 的 docstring 明写「**只证明内容没被换过，不证明签名有效**」（RS256 验签要 JOSE，
> 本包有意不做，`__init__` 的包文档里也写了这条限制，不许读成已验签）。
>
> **覆盖缺口写在产物里而不是写在承诺里**：`COVERAGE_GAPS` 六条——对话与事件流 `not-covered`、
> 协作与工单面 `internal`、管理面写操作 `partial`、**幂等键 `partial`（机制已强制，三处有意不接）**、
> OpenAPI `production-off`、真实第三方集成 `not-accepted`。**新面**：2 个只读端点 + 1 个响应头
> （`X-TT-Api-Contract`）+ 1 个重放头 + 1 个请求头（`Idempotency-Key`）+ 1 张新表 + 4 个错误码 + 2 个新模块；
> **零新依赖、零新环境变量、零 `ALTER`**。人读的 `tongtian-server/CONTRACT.md` **不在 W1 领地**，
> 生成器 `--emit-markdown` 的输出交给 W4 落文件。

## 4. 未验收与边界（不许被读成已做）

- **契约「可被第三方集成」未验收**：没有任何真实第三方按 `X-TT-Api-Contract` 打过一轮对话；
  台账与本分片都不得出现「已可被集成」字样。
- 自测全绿不等于实机绿：本轮跑的是**临时数据目录里的真实 uvicorn 进程**（真 HTTP、真 SQLite、真 JWT 验签），
  但不是 Docker 容器、不是旧卷升级演练、也没接网关。新表 `idempotency_keys` 的旧卷升级只做了
  「整表新建 ⇒ 不存在补列时序」的推理 + 自测里空表就位这一条，**没有在旧卷容器上真跑过**。
- `Idempotency-Key` **只覆盖 5 条写操作**，其余写操作（含 `admin` 面全部写操作）带键会被明确拒
  `IDEMPOTENCY_SCOPE_UNSUPPORTED`——不装作全库幂等。签发令牌的四条路径**有意不接**（见 §2 口径③）。
- 回执是 SQLite **明文字段**、24 小时 TTL、**不进备份底账**（`app/cli.py:BACKUP_LEDGER_TABLES` 有意未加
  `idempotency_keys`：它是临时缓存，不是「谁是谁、能干到哪、留了什么证据」的底账，且把响应原文吸进备份包
  等于自己造一处需要保密的副本——与既有注释「清单不该变成全库镜像」同源）。若 W4 认为该进，请回报，
  本窗口再改；这是**口径决定**不是遗漏。
- 契约的 `Depends` 名比对只对**真挂了依赖**的路径有效：`gateway/policy`、`engine/introspect`、`auth.logout`
  在处理器内部自查凭据，机器看不到，声明里靠 `auth-flow` 探针真打补。
- 429 相关数字（登录 50/IP、10/(ip,email)/300 s 等）本轮按源码模板逐字校验并真打到限流真的生效一次，
  但**不是压测**：只证明「数字真挡人」与 `Retry-After` 被读到，不证明并发容量。
- `tongtian-server/CONTRACT.md`（人读的那份）**尚不存在**——生成器 `--emit-markdown` 可产出，
  落文件要 W4 决定，不在 W1 领地。
