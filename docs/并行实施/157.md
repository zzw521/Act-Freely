## 4. 仍未做（不许被读成已做）

1. **四类远程后端全部未验收**：真 Docker daemon（本机 CLI 在但 daemon 没起）、真 PostgreSQL
   服务（本机无库，表存在性/权限/并发行为都没验）、真 S3/COS 桶与真凭据、真 SSH 主机。
   假端点绿只钉得住「命令行怎么构造、SQL 长什么样、签名齐不齐、key 前缀对不对、HTTPS 强制」，
   **不等于远程能用**。台账与界面都不许出现「已支持对象存储」。
2. **`keychain:` 引用未接线**：引擎进程里没有钥匙串访问件，`keychain:` 一律回
   「未接线 ⇒ 未验收」。所以「凭据进钥匙串」这条方案今天只落了**引用语法与被拒口径**，
   凭据实际只能来自 `env:`。
3. **桌面半边完全没动**（约束 C）：`src/shared/contracts_workspace.ts` 的
   `IPC_CHANNELS_WORKSPACE` 仍为空、`src-tauri/src/ipc/workspace.rs` 未加分支，
   `lib.rs` 与 `contracts.ts` 一次也没打开。界面目前**没有任何入口**能看见或切换工作区后端。
4. **`workspace_backend` 开关未接线** ⇒ 工具面 7 件今天全部不注册（§5 有请求）。
5. **资源与网络限制只到「解析 + 构造」层**：Docker 的 `cpus` / `memory` / `pids` / 只读挂载 /
   网络模式只钉住 `docker run` 的 argv 形状；PG 的角色配额、连接数、存储配额属数据库服务端；
   对象存储与远程主机的带宽、QPS 属对端策略——这三类本层无法强制，`probe()` 里已点名未验收。
6. **按人/按会话隔离的后端清单未落地**：注册表是**进程级全局**的，所以端点面对远程身份
   整条车道 403（`WS_DESKTOP_ONLY`）。这是当前唯一诚实的处置，不是「只给查询」的降级方案。
   服务化部署要用这条车道，得先做清单的多租户隔离。
7. **审计没有消费端**：只落 JSONL，界面不展示，也未并进 D-03 的统一审计视图。
8. **本地后端与既有 D-03 沙箱是「共用配置」而非「共用一个执行体」**：远程后端才走三段判定；
   本地后端的文件读写仍由常驻六件与 Rust 执行面负责，本刀**没有**把它们改道，
   也没有给本地后端开放 `exec`（本地执行一律 403 `WS_CAPABILITY_DENIED`）。
9. **`src-tauri/staged-engine/` 里还没有本轮三个新文件**——改 `engine/` 后必须
   `npm run build`（或单跑 `node scripts/stage-engine.mjs`）才进桌面包，否则实机跑的是旧引擎。
