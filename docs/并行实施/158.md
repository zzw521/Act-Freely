## 2. 口径句（供「更新N」条目使用）

> **D-23 服务端半边（W1 #158）**：组织级预算过去没有落点——引擎 `_quota_error` 只读**令牌声明里**的
> `quota.monthlyTokens`/`concurrentTasks` 并且拿**它自己的本地台账**做判定，服务端既没有组织额度这一档，
> 也没有任何地方能把「组织还剩多少」压进声明。本轮把收敛点收在**唯一一处** `app/auth.py:_issue_tokens`
> （登录 / 刷新 / 换设备五条签发路径全部经过它）：`resolve_member_quota()` 按
> 「个人显式覆盖 > 组织成员默认 > 角色缺省」三档算出成员级两数，`enforce` 打开时再按组织剩余**收敛**，
> 收敛后的数字直接写进 JWT 声明，**引擎侧一行未改**就按新数拦停。**四条口径先钉死**：
> ① **0 = 不限制**，不是「额度为零」（与引擎 `monthly > 0` 才拦同一口径），所以收敛**绝不写 0**——
> 剩余为 1 就收敛成 1，剩余不为正就**拒发令牌**（`403 ORG_BUDGET_EXCEEDED`）而不是发一份「无限」声明，
> 方向反了就是静默放开；个人填 0 的成员在组织一设预算后同样被当作 +∞ 收敛。
> ② **组织已用按 `usage_rollup` 行上盖章的 `org_id` 归集**（上报时刻人在哪个组织就记哪个组织），
> 直接复用 `gateway_usage._is_deduped` 的行过滤，与 `/api/v1/admin/usage/departments` **同一套算法**，
> 所以「逐部门相加 = 组织总量 = 个人明细之和」不是三套口径碰运气。
> ③ **服务端只看得见已上报用量**，引擎侧在途用量不计入 ⇒ 预算判定天然滞后，这条连同「声明是**签发时刻**
> 快照（存续期间不会被自动改小）」「并发档只收敛单人声明不收敛组织总数」「平台管理员不受拦停」四条一起
> 写进 `budget` 响应的 `disclosed`，不装作实时。
> ④ **`enforce` 缺省关闭** ⇒ 没有 `org_quotas` 行的旧卷升级后**逐字节等于升级前**（不收敛、不拦停、
> 报表照出），拦停要管理员显式打开；`PUT …/quota` 只在**拦停开关真的翻转**时吊销该组织在用会话
> （改额度本身不改「能不能登」，不动会话），并把 `sessionsRevoked` 与剩余 `activeSessions` **两个数都给**，
> 因为只报「还剩几个在用」会让管理员以为没影响到任何人。**管理员豁免**是防自锁：预算耗尽时唯一能加预算的人
> 若登不进来，这个组织就再也出不来——豁免在签发回执 `reasons`、预算页 `disclosed` 与成员 `caps[].exempt`
> 三处明写，且管理员的行**不参与超售加总**（他的数字不是承诺）。**超售判定**补了「不限制」这一维：
> 成员上限之和只加有额的，组里只要还有人不限额而组织预算有限，就如实标 `overCommitted` 并给出
> `overCommitReason`——0 不能相加，把它当 0 计入会把明显超售的组织读成安全。
> **新表 `org_quotas` 走 SCHEMA 整表新建**（`app/db.py` 追加在 `audit_anchors` 之后），**零 `ALTER`、
> 索引与建表同批**，因此不存在「索引早于补列导致容器启动崩溃」那类升级顺序面（W1 专属约束 A）；
> 备份契约 `tt-server-backup.v1` 的底账表加这张（「谁能花多少」是账，不是缓存）。
> CLI 侧新增 `orgs` 命令组六个动作，走同一份 `tt-server-cli.v1` 信封。

## 3. 状态明细（D-23 一节建议新增一段）

**进展（2026-11-04，W1 #158 落地服务端半边）**

- **组织模型有载体**：新表 `org_quotas`（`org_id` 主键 + 组织两档 + 成员默认两档 + `enforce` +
  `updated_at_ms/updated_by`），组织行本身沿用既有 `orgs` / `departments` / `user_departments`，
  没有另起一套组织结构。**两级**＝组织总额（月度 token 预算 + 并发上限）在上，成员级在下，
  成员级再分「个人显式覆盖 > 组织成员默认 > 角色缺省」三档，落点来源逐人在响应里给出（`source`）。
- **六个管理面端点**（全部 `require_admin`）：`GET /api/v1/admin/orgs`（清单：配额 + 当期已用一屏）、
  `POST /api/v1/admin/orgs`（建组织 / 同名即改名，入审计链 `org.create` / `org.rename`）、
  `GET|PUT /api/v1/admin/orgs/{org}/quota`（读 / 部分改；空入参 `400 NOTHING_TO_UPDATE`，
  未声明字段 `422`，不存在 `404 ORG_NOT_FOUND`，写审计 `org_quota.set` 带 before/after）、
  `GET …/budget`（裁决页：额度 / 已用 / 剩余 / 判定 / 超售 / 归属 / `disclosed`）、
  `GET …/members`（每人**下一次签发**会拿到的两个数、来源、是否被收敛或拦停）。
  路由注在 `market_router` **之前**（`/api/v1/{plural}/{item_id}` 通配会吞掉 `/admin/orgs`，
  这条坑是 #142 真机演练抓到的同源问题）。
- **签发处生效**：`_issue_tokens` 现在把 `resolve_member_quota()` 的结果写进声明，响应新增
  `quotaResolution{org,enforced,clamped,source,reasons,snapshot}`，且 `profile.quota` 与声明**同源**
  （界面与拦停不各说各话）；被拦即 `403 ORG_BUDGET_EXCEEDED`，中文原因点名用了多少 / 额度多少。
- **CLI 面**：`tt-server orgs list|create|quota get|quota set|budget|members`，`quota set` 的
  旗子只发用户真填的那些（`--monthly-tokens 0` 真的发 0，`or` 会把 0 当「没填」丢掉的老坑已在 #142 修掉）；
  命令回显到叶子动作 `orgs quota set`，便于脚本对齐。
- **本刀自测抓出的六个真缺陷**（都不是「测试写错了」，是实现跟不上语义）：
  ① `remaining < monthly` 在 `monthly == 0` 时永假 ⇒ **不限额成员在组织只剩 1 token 时照样拿到
  「不限制」声明**，拦停对它反向失效；改成把 0 当 +∞ 比、收敛下限取 1。
  ② 拦停翻转后响应里的 `activeSessions` 报的是**吊销之后**的剩余数（恒为 0），管理员会读成「没影响任何人」；
  改成 `sessionsRevoked` + `activeSessions` 两个数与一句 `statement`。
  ③ `sumMemberCaps` 把不限额成员按 0 相加 ⇒ 超售组织被读成安全；新增 `uncappedMembers` 与 `overCommitReason`。
  ④ `org_members()` 的 `SELECT` 漏了 `org_id`，而 `resolve_member_quota()` 要读它 ⇒ 「查一次预算」
  会在只读路径上抛 `IndexError`（`sqlite3.Row` 越界，最难查的那类）；补列并把所有字段读取收进
  容错的 `_value()`。
  ⑤ 自测里两条**假断言**（`check(..., True)` 与 `... != 1 or True`）看着绿其实什么都没测；
  删掉一条、另一条改成「关掉拦停后声明必须回到未收敛的个人值 30000 且 `clamped/enforced` 均为假」。
  ⑥ 旧卷升级用例最初**手工抄了一份 users/usage_rollup 的 DDL**——抄出来的表和真实 SCHEMA 会漂移，
  「测过了」等于没测；改成用 SQLite 在线备份 API 把在线库整份快照、只 `DROP TABLE org_quotas`，
  再跑真实 `init_db()`，最后比对升级后的列集合与在线库**一字不差**。
  另有一条不是缺陷但改了口径：模块文档原本写「豁免在响应的 `bypass` 里明写」，实现里根本没有这个键，
  已改成点名真实字段（`reasons` / `disclosed` / `caps[].exempt`）。
- **第七条是复核分片自己的说法时抓到的**（写「六个端点都带契约版本」前先去数了一遍，结果只有五个）：
  `POST /api/v1/admin/orgs` 的响应漏了 `contractVersion`，而 CLI 的 `orgs` 六个动作里
  `create / quota get / quota set / budget / members` **五个都把服务端契约版本丢掉了**
  （只有 `list` 透传）——同一命令组内部两种形状，脚本按 `data.contractVersion` 统一断言会时灵时不灵。
  已补齐：六个端点响应一律带 `tt-org-quota.v1`，CLI `orgs` 六个动作一律透传，
  并新增 5 项自测钉住（`quota set` 同时把 `sessionsRevoked` 带到机器面，运维在命令行也能看到
  「这次踢下线了几个人」）。补完后 `org_quota` 族 121 → 135，`cli` 族仍 261 无退。

## 4. 未验收与边界（不许被读成已做）

- **引擎侧的「组织总闸」未验收**：本轮把预算压进**单人声明**，引擎按声明拦停是它既有行为（未改引擎）；
  「同一组织 N 个人同时跑，总数不超过组织并发上限」这条**需要执行面计数**，本刀只在 `disclosed` 里
  明写了「并发档收敛的是单人声明」。**没有做跨成员的同时任务计数。**
- **未开真机多设备演练**：桌面台账与上报滞后是真实风险但本机无第二台设备 / 无真实多组织生产数据，
  所有跨设备台账分歧都是**推理**而非实测。
- **拦停默认关** ⇒ 现网升级后**不会自动开始拦停任何人**，这是刻意的；界面/文档若把它读成
  「组织配额已生效」属于误读，必须显式 `enforce on`。
- **`quotaResolution` 是新键**：桌面 `src-tauri/src/auth/service.rs:468` 只按 `accessToken` 取值
  （`serde_json::Value` 宽松读取，Rust 侧无 `deny_unknown_fields` 用在登录响应上），全仓 TS/Rust
  **没有任何契约测试读 `tongtian-server/app/auth.py` 或钉登录响应的键集合**（已 grep 验证：
  `profile_of` 在 TS 里唯一的命中是 `agent-efficiency-contract.test.ts` 钉的 **Rust** 同名函数，
  与本刀的 Python 函数无关）。因此这一改动对既有消费者惰性——但**它确实是响应形状变宽**，
  按规则 7 在此声明，而不是留到别人放闸时发现。
- **本刀改了既有函数签名（向后兼容，独占领地内）**：`app/auth.py:profile_of(user)` →
  `profile_of(user, quota=None)`；`set_org_quota()` 返回值由 `dict` 改为 `(dict, int)`（全仓**唯一**
  调用点就是本模块的路由，已同步）。没有改任何跨语言形状，所以没有需要同步的 pin。
- **`orgs` 界面零**：控制面 `app/web/**` 没有组织配额页，能力目前是纯 API + CLI。
  本轮未动 `app/web/**`（虽在领地内，但界面属另一刀的活，不顺手做）。
- **SSO / OIDC / SCIM 零**：D-23 方案里这三件一行未动。
- **桌面切账号（ACC-07）零**。
- **旧令牌不追溯**：`enforce` 打开只吊销**在用会话**；已经用旧额度算出来的**引擎本地台账**不回滚，
  已消耗就是已消耗。
- **配额数字没有货币维度**：只有 token 与并发两档，「计费 / 超额策略」那条（台账 §1563 计费与配额模型）
  不在本刀。
