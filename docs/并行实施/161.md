## 2. #161 落地了什么（工程事实，给要接手的窗口）

**① 写暂存只有一个判定入口。** `engine/write_staging_runtime.py`（977 行，纯标准库）把文本写入拆两步：

- `stage(new_text, target=…, task_id=…, tool=…, work_dir=…)`：新内容写进数据根下的
  `write-staging/`（`data_paths.write_staging_dir()`，本模块不解析环境变量），**目标文件一个字不动**，
  同时对着盘上那一份算 unified diff。暂存目录刻意**不在工作目录里**——工作目录是模型能写的地方，
  把待审批正文放那儿等于让被审批者改自己的审批对象。
- `apply(change_id)`：合并前**重算目标指纹**。目标在暂存之后被另一条通道直接写盘、被用户在编辑器里改了、
  或被删了，就拒绝合并并标 `expired`，绝不拿一份对不上事实的 diff 去盖现在的内容。
  这一步是整个功能的意义所在：逐工具审批弹的「是 / 否」框在没有 diff 时等于签空白支票。

开关口径：`staging_enabled(runtime)` 是**唯一**判定入口（`build_agent` 与逐工具审批网关共用它），
它读 runtime 载荷的 `writeStaging` / `write_staging`（裸字符串或对象都收）。留一个函数而不是两边各写一遍
`from_runtime(...).staged`：接管范围一叉就会出现「暂存没开、审批却少弹一次」——那是少一道审批。
缺省 `off`：关掉时 `stage` 回 `staged=False`，调用方按改造前的路径原样写盘，**回执逐字不变**。
上限（正文大小、待审阅条数、保留期）一律如实拒绝，**不退化成直接写**——开着暂存却把内容原样落盘，
就是当着用户的面把承诺撤回。每次决定追加一行 `decisions.jsonl`，**只记指纹与字节数，不记正文**。

**② 人格模板不是新存储。** `engine/persona_runtime.py`（488 行）16 套 MBTI 模板（四组各 4 套、
提示词实测 279–312 字），三条刻意设计写进 docstring：

- 注册表权威仍在 Rust `experts.registry`（一份 settings_kv），本模块只产**草稿**；再造一份「模板库」
  就是再造一份「谁说了算」。
- 行为风格折进提示词，**不给 `Expert` 加字段**：跨语言新增 `personalityStyle` 要动 Rust 结构体 +
  契约 + 引擎 `expert_runtime._ITEM_FIELDS` 三处，而这字段除了拼进提示词没有任何消费者。
  模板内部把「风格」与「职责」分开维护、导出时合成一段——分的是**编辑粒度**，不是存储字段。
- 上限与 Rust 同源：`MAX_PROMPT_CHARS` 从 `expert_runtime` 取（`er.MAX_PROMPT_CHARS`），
  其余六条常量在本文件的 `_limits()` **唯一构造点**；自测用正则回读
  `src-tauri/src/expert/mod.rs` 的 7 条 `const MAX_*` 反向核对（D-48.4b 的教训：两边各写一遍数字，
  迟早有一边跟不上）。

预校验按「**不过严也不放松**」对齐 `expert::save`：`normalize_id` 是 trim + 小写，`normalize_input`
是 trim 后按 `chars().count()` 量长度，技能**先去空串与大小写去重、再**按 `MAX_SKILLS` 计数，
长度都按归一后的值量。因此大写 id 是归一不是拒绝——「会按小写保存」这类话走 `normalization_notes()`
独立通道；混进 `problems` 会把 `ok` 翻成 false（写的时候真踩了这一下）。

**③ 车道与契约。** `engine/routes_exec.py`（403 行）现 13 条端点 = 写暂存 7（`status` / `pending` /
`change` / `decisions` / `apply` / `reject` / `discard`）+ 人格模板 5（`templates` / `template` /
`draft` / `validate` / `status`）+ D-08 的 `/api/exec/extensions` 1。

- 写暂存族**只对桌面壳开放**（`STAGING_DESKTOP_ONLY`）：列待审阅会把别人正待写入的正文与目标绝对路径
  交给调用方，`apply` 更是一次真实写盘。
- 人格模板族**刻意不套桌面闸门**：经手的只是代码常量表与一份没保存的草稿，不含用户数据也不写任何存储，
  按普通引擎鉴权走；拿 `STAGING_DESKTOP_ONLY` 拦它反而让远程用户连「有哪些角色」都看不见。
  这条差异写进模块 docstring 并由自测钉住。
- 业务性拒绝（过期 / 找不到 / 位置越界 / 未知模板 / 坏分组）回 **200 + `ok=false` + 中文 `reason`**；
  只有读不出来的意外才回 500 带错误码。`PERSONA_BAD_REQUEST` / `STAGING_*` 是「单独字段里的码」，
  不落在 `error-surface-contract` 的采集式（`/["']([A-Z][A-Z0-9_]{3,}):/g` 要求冒号在字面量内），
  已核实渲染层零引用，因此**不需要**在 `error-messages.ts` 登记。
- **零新增 IPC 通道**：`IPC_CHANNELS_EXEC` 仍空，渲染层走 `engineFetch`。
  `src/shared/contracts_exec.ts` 补 `Persona*` **八个**接口（`PersonaTemplate` / `PersonaLimits` /
  `PersonaTemplatesResponse` / `PersonaTemplateResponse` / `PersonaExpertDraft` /
  `PersonaDraftResponse` / `PersonaValidateResponse` / `PersonaStatusResponse`），
  自测用运行时采集的实际回话键集（`SEEN_KEYS`）与 TS 接口**双向对键**。

**④ 引擎写路径已经接上。** `server.py:1782` 把 `wsr.staging_enabled(session.runtime)` 写进

## 6. 写这刀时撞出的三个自测缺陷（都已改掉，留给别人当写用例的前车）

1. **模板清单浅拷贝**：`list_templates` 用 `dict(t)` 把 `style` 列表原样交出去，一次 HTTP 调用就能把
   进程级常量表改脏**整个会话**。现 `_copy()` 连 `style` 一起克隆，`get_template` 同，
   自测用 `_list_is_copy` / `_get_is_copy` 正面钉住。
2. **分组判据写错暴露内容错位**：我按「第 2–3 字母」实现 Keirsey 分组（ISTP / ESTP 应该都在探险家组），
   改对成「第 2 字母，S 类再看第 4 字母」之后，同一把尺子立刻量出 **ENFJ / ENFP / ESFJ 三套的维度串
   不是 MBTI 字母序**，以及 **ISFP 模板名与分组名撞名**。教训：判据写错时，反复制粘贴的那一节
   会顺手把内容缺陷也抓出来——所以那节不能删。
3. **断言挂错分支**：「只读不写」这句原本挂在失败分支的 `note` 上，而失败分支说的是 `expert::save`
   未接线。首轮 1 红就是这个。拆成两条正反向断言（成功分支含「只读不写」、失败分支含 `expert::save`）。

另外三处口径值得单独记：`validate_expert_draft` 只回**真拒绝**、提醒另走 `normalization_notes`；
`_limits()` 是上限字典的唯一构造点（`draft_from_template` 与 `catalog_status` 都从它取）；
「上限数字出现在 docstring 里」不能当断言证据——自测扫的是 `_code_tokens()`（tokenize 只取代码 token，
跳过字符串），否则文档改了、代码没改也会绿。
