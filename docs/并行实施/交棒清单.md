## 2. 加一条引擎端点

在自己的 `engine/routes_<lane>.py` 里 `@router.get("/api/...")` 就行，`server.py` 不必打开：

- 车道**挂在既有路由之后**：`server.py` 末尾的 `ROUTE_LANE_REPORT = rln.attach(...)` 一次性挂载，
  七条车道按上表顺序挂，**既有 61 条路由永远优先**。
- 四种写法会被当场拒绝并抛 `LaneError`（引擎宁可不起也不带半套路由跑）：
  越界前缀（前缀**按段**对齐，`/api/artifact` 不算 `/api/artifacts` 的本家）、
  车道名未登记、同车道内重复挂载、**被既有通配吞掉的字面路径**
  （D-07.4 真机演练踩过「通配路由吞掉 `revoked.json`」，mock 永远测不出来）。
- **不许 `import server`**。要引擎现场（会话表、鉴权、既有工具）用 `routes_lanes.engine()`，
  它在 `attach()` 时绑定；车道内直接 `import server` 会因为「`__main__` 与被导入的 `server`
  两种身份」造出第二份会话表。

## 4. 加一条 IPC

只动两处自己的文件：

1. `src/shared/contracts_<lane>.ts` 的 `IPC_CHANNELS_<LANE>` 加一条通道，值必须是
   `'<lane>:<method>'`，**冒号后半段就是 Rust 侧的 method 名**，两边不许各改各的。
2. `src-tauri/src/ipc/<lane>.rs` 的 `dispatch` 加一条 `match` 分支。

渲染层照常 `systemAPI`/`invoke` 走原通道名即可：`src/renderer/lib/tauri-api.ts` 顶部有唯一一条
分派分支，按 `src/shared/ipc-lanes.ts` 的登记表把 `<lane>:*` 路由到
`lane_<lane>(method, payload)`。**`lib.rs` 与 `contracts.ts` 都不用打开。**
未实现的方法回 `IPC_LANE_NOT_IMPLEMENTED:<lane>::<method>`，调用方按失败处理，别当成功读。
