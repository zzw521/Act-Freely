dingtalk-stream==0.24.3

# 同钉钉一样只借协议，传输仍走上面的 aiohttp；它的 websockets / cryptography / certifi

wecom-aibot-python-sdk==1.0.2

# 飞书长连接通道的协议来源：官方 SDK 的握手端点、帧头键名、错误码与 protobuf 分帧
# （lark_oapi.ws.const / ws.enum / ws.model / ws.pb.pbbp2_pb2.Frame）。飞书与前两家不同，
# 它的帧不是 JSON 文本而是 protobuf 二进制 envelope，自己照文档手搓字段名迟早和线上对不上。
#
# 代价必须写清楚，否则下一个人会把它当普通依赖在引擎启动时 import：
#   * 根包 `lark_oapi/__init__.py` 里有一句 `from .api import *`，会把上万个生成的
#     OpenAPI 模型全部加载 —— 本机实测 import 一次 11120 个模块、7.7~13.2 秒。
#     所以 engine/feishu_channel.py 只能在模块里用 find_spec 探测（0.03 秒），
#     真正 import 推迟到用户点「启动连接」那次，不能让引擎启动陪它等十秒。
#   * 解压 20.3 MB / 10733 个文件，比钉钉（+0.4 MB）与企业微信（+0.26 MB）大两个量级。
#   * 它声明 websockets<16，和钉钉/企业微信一起解析出来的唯一可用版本是 15.0.1，
#     于是随包运行时的 websockets 从 16.0 降一级。引擎自己从不 import websockets
#     （传输统一走 aiohttp），降级影响面只有那两家 SDK 自身的导入路径，
#     已由三条通道的引擎自测复验。
# 缺这个包时通道如实退回「尚未接入」，不会给一个必然失败的输入框。
lark-oapi==1.7.5
