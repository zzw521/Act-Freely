通天办公

一款本地优先、自主执行的桌面端 AI 智能工作助手。你说需求，它交付结果——并支持任意大模型的自定义接入，让企业把 AI 能力掌握在自己手里。

目标用户知识工作者 / 企业团队
核心差异模型自定义接入 + 清新体验
形态macOS / Windows 桌面客户端

1产品概述

1.0 问题定义与量化痛点

1.1 背景与机遇

传统 AI 工具的模式是「你问、它答，动手还得靠自己」。随着 Agent（智能体）能力成熟，工作助手正从「对话问答」升级为「自主规划—执行—交付」。以 QoderWork 为代表的桌面 AI 智能体，已验证「自然语言描述目标 → 自动拆解任务 → 本地执行 → 交付成品」的产品范式在办公场景的可行性与高价值。

但在实际落地中，企业普遍存在一个刚性诉求：模型不可控。公有云大模型在数据安全、合规、成本、特定领域效果上存在顾虑，企业希望接入自有的通义千问、DeepSeek、GLM，乃至私有化部署 / 本地模型（Ollama 等）。这正是「通天办公」相比同类产品的核心差异点与机会窗口。

1.2 产品定位

通天办公 = 一个本地优先的桌面 AI 工作智能体 + 一套开放可插拔的模型接入层。

  • 对个体：把文件整理、数据处理、文档创作、浏览器操作、定时任务交给 AI，从「重复劳动」中解放。
  • 对团队 / 企业：自定义接入自有模型与内部系统，数据不出域、成本可管控、效果可定制。

1.5 非目标与范围边界（Out of Scope）

  • 不自研基础大模型：专注模型接入、编排与体验，底层能力由接入的模型提供。
  • 不替代专业重型软件：不做 Photoshop、IDE、CAD 等垂直专业工具的能力替代。
  • 首版不做移动端：桌面优先（macOS / Windows），移动端列入后续规划。
  • 不做实时音视频通话：聚焦异步任务自动化，而非即时通讯内核。
  • 不承诺 100% 自动化成功率：复杂/高风险操作需人工确认，以可控为先。
  • 不做通用搜索引擎：信息检索依赖模型与已授权数据源，不重建搜索。

3用户画像与使用场景

👤 知识工作者（个人）

办公人员、分析师、内容创作者。文件杂乱、重复劳动多。

典型场景：整理下载文件夹、汇总多份报表、把数据转成图表、定时生成日报。

🏢 企业 / 团队

有数据合规与成本要求，需接入内部系统。

典型场景：接入私有模型处理合同、打通钉钉/飞书下发任务、统一计费与权限治理。

场景示例（清新一句话指令）：
「把本周销售 CSV 整理成带趋势图的周报，用我接入的本地模型分析，发到飞书群里。」——通天办公自动规划、调用本地模型、生成图表、推送结果。

4功能模块分解

按子系统→模块→子功能三级梳理全部产品能力，标注优先级：P0 必备 P1 重要 P2 增强。

4.1 智能对话工作台（Agent 引擎）P0

4.1.1 任务理解与规划

  • 自然语言目标解析：从用户口语化描述中抽取意图、实体与约束
  • 多步骤任务分解（Plan & Step）：生成结构化执行计划，每步含类型/输入/可回滚标记
  • 计划可视化与人工审阅：以卡片流展示 Plan，用户可批准/拒绝/修改每一步

4.1.2 自主执行引擎

  • 步骤顺序/并行执行调度：依赖分析后自动编排，无依赖步骤可并行
  • 工具调用编排：统一调度 LLM 调用、文件操作、浏览器操作、桌面控制
  • 实时进度推送：每步执行状态通过 SSE 流式回传前端
  • 中断/恢复/回滚控制：任意时刻可暂停、续跑、或回滚到指定步骤

4.1.3 交付与反馈

  • 产物预览与确认：文件变更、生成内容在交付前可预览
  • 迭代 Refine 对话：交付后支持追加指令修正，形成多轮优化闭环
  • 执行历史与审计日志：每次任务完整记录 Plan/Step/FileOp，可回溯可导出

4.2 模型接入层（Model Hub）P0

4.2.1 预置模型管理

  • 通义千问 / DeepSeek / OpenAI 一键启用（需用户自备 Key）
  • 模型能力画像与推荐：接入后自动跑标准评测套件，生成能力雷达图

4.2.2 自定义模型接入

  • OpenAI 兼容 API 表单接入：填 Base URL + Key + 模型名 + 上下文长度即接即用
  • Ollama 本地模型：自动发现本地运行中的 Ollama 实例与模型列表
  • 企业模型网关对接：支持通过内网网关统一鉴权与审计

4.2.3 模型路由与策略

  • 全局默认模型：新对话兜底
  • 按智能体绑定：财务分析走本地、创意文案走云端
  • 按数据敏感度自动切换：检测到 PII 强制本地通道
  • 降级熔断与自动切换：超时/限流/高错误率触发备用模型

4.2.4 用量与成本监控

  • 按模型/用户/任务三维度统计 Token 消耗与预估费用
  • 月度预算上限设置，超额自动降级或暂停
  • 审计日志导出（CSV/JSON），支持对企业对账

4.3 文件处理中心P0

4.3.1 多格式读写

docx / xlsx / pdf / csv / txt 全覆盖，保留原格式与样式

4.3.2 智能整理

按类型/时间/主题分类、去重检测、批量重命名

4.3.3 格式转换

pdf ↔ docx、xlsx → csv、多源信息提取与合成

4.3.4 操作安全保障

  • 写操作前自动备份原文件至 .tongtian-backups/
  • 操作失败自动回滚至备份
  • 沙箱隔离：仅可访问用户授权的工作目录

4.4 自动化能力集 P1

4.4.1 浏览器自动化

  • 自动导航网页、填写表单、提取结构化数据
  • 支持多步骤 Web 操作流程，无需编写脚本
  • 内置 Playwright 驱动，支持 Chromium

4.4.2 桌面应用控制

  • 模拟点击、键盘输入、滚动，操控任意桌面应用
  • 受权限与沙箱约束，关键操作需人工确认

4.4.3 定时任务编排 P1

  • 周期性任务（每日/每周/Cron 表达式）
  • 一次性预约任务
  • 后台静默执行，失败自动告警

4.4.4 IM 集成 P1

  • 钉钉 / 飞书机器人接收指令
  • 任务完成后推送结果到群聊
  • 消息链路串联，实现「手机发指令→桌面执行→手机收结果」

4.5 扩展生态 P2

4.5.1 MCP 协议支持

社区 MCP 服务器即插即用，接入外部工具与数据源

4.5.2 自定义技能/工作流

可视化编排可复用的自动化模板，团队共享

4.5.3 开放 API

RESTful / WebSocket 接口供企业二次开发，对接内部系统

4.6 记忆与个性化 P1

4.6.1 跨会话上下文记忆

记住用户偏好、常用工作目录、历史任务模式，新对话带完整上下文开始

4.6.2 记忆管理

可视化查看已存储的记忆，支持纠正错误记忆、清除指定记忆、一键重置

4.6.3 用户偏好学习

从交互中学习输出格式偏好、模型选择倾向、确认粒度习惯，逐步减少人工干预

4.7 安全与治理 P0 安全基线 / P2 企业版

4.7.1 数据分级与出域合规

  • 自动识别合同/PII 等敏感内容并标记分级
  • 出域白名单：仅授权模型可接收敏感数据
  • 硬开关：企业策略可一键禁用所有外部 API

4.7.2 密钥加密存储

  • API Key 通过系统密钥库（keytar）加密持久化
  • 运行时解密至内存，绝不明文落盘
  • .env 仅放占位示例，严禁真实密钥

4.7.3 SSO / RBAC 企业版

SAML/OIDC 单点登录，基于角色的权限控制（管理员/成员/只读）

4.7.4 全链路审计

  • 模型调用、文件操作、路由切换全程留痕
  • 审计日志支持筛选、导出、定期归档
  • 敏感字段（Key、文件路径中用户名）自动脱敏

5用户故事 (User Stories)

按三类角色展开，每个故事包含：角色 + 目标 + 动机，并附验收标准。

5.1 知识工作者（个人用户）

US-01 一句话整理下载文件夹

作为办公人员，我想要用一句话指令让 AI 自动整理杂乱的文件，以便从重复劳动中解放，聚焦高价值工作。

验收标准
输入「整理下载文件夹，按类型分类」后，Agent 自动生成包含「扫描→归类→移动→命名→预览」的计划
计划审阅后可一键执行，完成后展示分类结果与文件数量统计
操作前自动备份，支持一键回滚至整理前状态

US-02 多份报表自动汇总成周报

作为数据分析师，我想要把多份 Excel/CSV 自动汇总成带图表的周报，以便省去手工复制粘贴和排版的数小时。

验收标准
选中 ≤10 个数据文件，一句话描述汇总维度，Agent 自动读取、合并、去重、计算汇总值
自动生成趋势图（折线/柱状）并嵌入 docx 或 Markdown
输出格式可选（docx/pdf/md），样式整洁可直接发送

US-03 用本地模型处理敏感合同

作为法务人员，我想要用纯本地的 Ollama 模型分析合同条款，以便杜绝机密文本外泄到云端 API。

验收标准
在模型设置中将某智能体绑定至本地 Ollama 模型，并勾选「禁止外网」
上传合同 PDF，Agent 调用本地模型完成条款摘要、风险点标注、合规建议
可通过网络监控验证全程无数据包外发至非本地地址

US-04 定时生成日报并推送飞书

作为项目经理，我想要每天 18:00 自动汇总当日工作并推送到团队飞书群，以便团队成员无需手动同步进度。

验收标准
创建定时任务，设置 Cron 0 18 * * 1-5，绑定任务模板「日报汇总」
任务按时触发，汇总指定目录下的当日修改文件，生成日报摘要
通过飞书 Webhook 推送至指定群聊，附带简要统计卡片

US-05 浏览器自动抓取竞品价格

作为运营人员，我想要让 AI 自动打开竞品网站抓取价格表并保存为 Excel，以便持续跟踪市场动态。

验收标准
描述目标 URL 与抓取字段（产品名、价格、促销），Agent 自动导航、提取、结构化
结果保存为 xlsx，支持追加模式（每次抓取新一行，不覆盖历史）
遇到反爬/验证码时暂停并提示用户介入，不无限重试

US-06 接入自有 API Key 的 DeepSeek 模型

作为技术爱好者，我想要用自己申请的 DeepSeek API Key 替代预置模型，以便使用更高配额和更优性价比。

验收标准
在「模型管理→自定义接入」填入 Base URL + Key + 模型名，点击「测试连通性」
自测通过后显示模型信息（上下文长度、延迟），可设为全局默认
对话中可随时在多个接入模型间切换，切换后立即生效

5.2 团队管理者

US-07 统一团队模型配置与成本管控

作为团队 Leader，我想要为团队统一配置模型并设置月度预算上限，以便控制 AI 使用成本防止失控。

验收标准
管理员可配置团队共享模型池，成员无需各自填写 Key
按模型设置月度预算（如 DeepSeek ≤ ¥200、云端 GPU ≤ ¥500），超额自动降级或暂停
账单按成员/模型/项目维度拆分明细，月度自动汇总推送

US-08 任务模板共享与复用

作为团队管理者，我想要把常用自动化流程保存为模板并分享给团队，以便新人无需重复描述相同任务。

验收标准
执行成功的任务可「保存为模板」，包含 Plan 结构、模型绑定、输出格式
模板可分享给团队成员或设为团队默认，在「模板库」中一键调用
模板支持版本管理，修改后增量更新，不影响已使用旧模板的历史任务

US-09 敏感数据强制本地通道

作为管理者，我想要确保标记为「机密」的文档只能由本地模型处理，以便满足数据合规要求。

验收标准
管理员可定义敏感数据规则（如文件标签、路径匹配、关键词检测）
命中规则的文档自动路由至本地模型，禁止外部 API 调用
策略变更即时生效，已运行中的任务在下一步执行前应用新策略

US-10 审计日志审查

作为管理者，我想要定期审查团队的 AI 使用审计日志，以便发现异常用量或潜在数据泄露风险。

验收标准
审计看板展示模型调用 Top-N、异常时段、数据外发次数
支持按时间/成员/模型/操作类型筛选，导出 CSV 或 PDF 报告
异常行为（如非工作时间大量调用、新模型首次使用）自动告警

5.3 企业 IT 管理员

US-11 对接企业模型网关

作为IT 管理员，我想要将通天办公接入企业统一模型网关，以便复用已有鉴权、审计和配额体系。

验收标准
支持通过内网 URL + 企业 Token 对接网关，通天办公仅做协议适配不做额外鉴权
网关侧配额/限流/审计能力无缝衔接，模型调用自动继承网关策略
网关不可用时降级至本地模型或暂停任务，而非绕过网关直连外网

US-12 SSO 集成与 RBAC 权限配置

作为IT 管理员，我想要通过企业 SSO 统一管理账号和权限，以便员工入职/离职时自动开通/回收访问权限。

验收标准
支持 SAML 2.0 / OIDC 标准协议对接企业 IdP（如 Azure AD、Okta、飞书）
RBAC 三级角色：管理员（全量配置）、成员（使用+自定义模型）、只读（仅查看）
离职员工权限自动回收，历史会话数据按保留策略处理

US-13 出域合规硬开关管控

作为IT 管理员，我想要一键开启「出域合规硬开关」禁止所有外部 API 调用，以便在安全审查或攻防演练期间确保数据零外发。

验收标准
企业策略面板提供「仅允许本地模型」全局开关，开启后所有外部 API 调用被阻断
开关状态变更写入审计日志并通知所有在线用户
阻断时用户侧显示友好提示「管理员已开启数据保护模式，外网模型暂不可用」

6交互流程

覆盖核心业务场景的正常路径 + 异常处理，确保交付不中断、数据不丢失、用户可掌控。

6.1 主任务执行流程

三层执行沙箱架构 P0 安全基线

层级执行环境能力范围安全措施首版

  • 高风险操作二次确认弹窗

  • 单 Agent 最大 CPU 使用率限制
  • 内存上限（默认 512MB）
  • 磁盘写入速率限制
  • 超限自动降级或暂停

7.7.2 MCP 协议集成 P1

MCP（Model Context Protocol）是连接外部工具与数据源的行业标准协议。通天办公内置 MCP 客户端，让 Agent 安全可控地接入外部能力。

MCP 客户端架构

  • 服务发现：支持 stdio / SSE / Streamable HTTP 三种传输协议
  • 连接管理：自动重连、心跳检测、连接池
  • 工具注册：MCP 工具自动映射为 Agent 可调用的 StepType
  • 流式输出：工具调用中间结果实时推送至前端

安全控制

  • 工具白名单/黑名单：按 Agent、按用户粒度控制可调用工具
  • OAuth 2.1 认证：MCP 服务器的授权接入
  • 参数校验：zod Schema 校验工具调用参数
  • 调用频率限制：防滥用与成本控制

7.10 多智能体并行工作区 P1

通天办公支持在同一实例内运行多个独立的 Agent 工作区，每个工作区拥有独立的模型绑定、记忆空间、技能集和 MCP 工具集。多个工作区可并行执行，互不阻塞——让用户同时处理多项任务而无需等待。

  • 独立模型绑定：各自选择不同模型，互不影响
  • 独立记忆空间：工作区之间的记忆不共享（除非显式授权）
  • 独立技能集：每个工作区可启用/禁用不同 Skill
  • 独立 MCP 工具白名单：按工作区粒度控制可调用工具

8模型自定义接入能力 核心差异

这是「通天办公」区别于同类产品的最重要能力：构建一层模型接入层（Model Hub），让用户把任意大模型——云端厂商、开源模型、私有化部署、本地运行——接入产品，并按任务 / 智能体灵活绑定。

8.1 设计目标

  • 开放：兼容 OpenAI 协议的主流模型「填表即接」，零代码。
  • 可控：默认本地优先，敏感数据可强制走本地 / 私有模型。
  • 灵活：不同任务可绑定不同模型（如创意用云端、机密用本地）。
  • 可观测：用量、成本、延迟、质量全链路监控。

8.5 模型路由与绑定

  • 全局默认模型：新对话使用的兜底模型。
  • 按智能体绑定：「财务分析」智能体强制走本地模型；「创意文案」走云端。
  • 按数据敏感度：检测到合同 / 个人身份信息时，自动切换至私有模型（可配置）。
  • 降级与熔断：主模型超时 / 限流时自动切换备用模型，保障交付不中断。

8.10 企业出域合规策略

  • 数据分级：自动识别合同/个人身份信息(PII)等敏感内容。
  • 出域白名单：仅白名单模型可接收敏感数据；其余强制本地/私有通道。
  • 硬开关：企业策略可一键禁用所有外部 API，仅留本地模型。
  • 全量审计：模型调用、数据流向、token 用量留痕可导出。
  • 合规告知：接入第三方 API 时强制弹出数据外发告知与确认。

9界面设计规范（清新）

整体风格：浅色、留白、柔和、低负担。让用户专注内容本身，而非被工具包围。

配色

主色清新蓝 #3FA7F4，点缀薄荷绿 #2ED3B7；背景 #F5F9FB，卡片纯白。避免高饱和与重阴影。

排版

系统无衬线字体；正文 15px / 行高 1.75；标题层级清晰，留白充足。

组件

圆角 10–16px；轻阴影；开关、卡片、按钮统一手感；状态用柔和色区分。

布局

左目录 + 右内容；对话区为沉浸式单栏；设置页分组清晰、可扫读。

设计原则：少即是多。每一个界面元素都要回答「这能帮用户更快交付吗」。清新不是装饰，是降低认知负荷。

11数据安全与隐私

  • 本地优先：文件操作在设备完成，仅授权内容经模型 API 处理。
  • 最小授权：仅可访问用户明确授权的工作目录，越权需二次确认。
  • 私有模型通道：敏感任务可强制走本地 / 内网模型，数据零外发。
  • 可审计：操作日志、模型调用留痕，支持导出与清除。
  • 企业治理：SSO / RBAC / 集中策略（参考企业版基线）。

15商业化与定价模型

核心思路：产品价值 = 「自主交付能力」+「模型自定义接入」。定价围绕这两点设计——基础能力订阅 + 模型用量弹性 + 企业私有化增值，避免把差异化能力（自定义模型）锁死在单一价格档里。

15.2 自定义模型的混合计费逻辑

自定义接入是差异化卖点，计费上坚持「谁的模型、谁的成本」原则，不重复抽水：

☁ 预置 / 第三方云端模型

消耗订阅内的模型额度；超出部分按平台 Credits 计收（公示单价）。第三方 API 直接费用仍由用户向供应商支付。

🏠 本地 / 私有化模型

本地推理零边际 API 成本；平台仅收取席位 / 部署服务费，对企业最友好。

Credits 计量体系（可选）

  • 统一计量：把不同模型、不同模态的消耗折算为 Credits，跨模型统一看板。
  • 预算护栏：个人 / 团队可设月度预算上限，超额自动降级或暂停，防失控。
  • 透明账单：按模型 / 用户 / 任务导出明细，对企业对账友好。

15.3 增长与渠道

  • PLG 自传播：Free 版 + 一键分享「自动化任务模板」，靠口碑与场景扩散。
  • 企业直销：以「模型自主可控 + 数据不出域」切入有合规刚需的行业（金融、政务、制造）。
  • 生态合作：与模型厂商、私有化部署方案商联合推广，形成「通天办公 + 你的模型」捆绑。
  • 教育与开源：对学生 / 教育者提供减免，培育未来用户。

16风险与依赖

以下为立项阶段识别的关键风险，需在研发与上线前明确缓解方案与负责人。

16.1 风险清单

风险类别等级影响缓解方向
Agent 误操作 / 越权执行技术高损坏文件、错误外发沙箱隔离、关键操作人工确认、可回滚
自定义模型安全（第三方 API）安全高凭证泄露、数据外发密钥本地加密、出域合规硬开关、审计
数据出域 / 跨境合规合规高监管处罚、信任崩塌数据分级、白名单、合规告知与同意
MCP / 连接器生态不成熟生态中能力扩展受限自研核心 MCP、开放协议共建
巨头竞争挤压竞争中差异化被复制强化模型自由 + 清新体验壁垒
模型成本波动运营中毛利不稳Credits 护栏、混合接入降本
本地运行时（Ollama）兼容性技术低本地模型体验差提供适配清单、一键安装指引

16.2 外部依赖

  • 模型供应商：通义千问、DeepSeek、OpenAI 等 API 的可用性、限流与定价变动。
  • MCP 生态：社区连接器质量与维护，决定「最后一公里」能力。
  • 云基础设施：预置模型调用、对象存储等依赖主流云平台稳定性（需立项后核实最新规格）。
  • 本地运行时：Ollama / vLLM 的版本演进与硬件适配。
  • IM 平台 API：钉钉 / 飞书接口的开放程度与配额。

16.3 关键缓解原则

默认安全、最小授权、可审计、可回滚——这是贯穿技术架构与运营的全部底线。任何「自动化提效」都不应以牺牲数据安全与可控性为代价，尤其在企业版。
